# 外部组件集成说明（V1.0.2）

> 本文档覆盖模块 **B2 / B5 / C3 / D2 / D5 / D6 / E3 / F3** 中涉及的七大外部技术组件的接入方式、默认行为（Mock）与生产切换（真实）方法，以及联调验证结论。

---

## 1. 总体架构范式

所有外部组件统一采用 **「接口 + `@Primary` Mock 实现（默认）+ 真实实现（按需开启）」** 的可切换范式：

- 每个组件定义 Java 接口（如 `StorageService`、`FundEscrowService`、`SearchService`、`DelayQueueService`、`ContentAuditService`、`LogisticService`、`RiskEngine`）。
- Mock 实现标注 `@ConditionalOnProperty(name="idlefish.<comp>.mock", havingValue="true", matchIfMissing=true)`，作为默认实现，**沙箱/演示零依赖即可跑通链路**。
- 真实实现标注 `@ConditionalOnProperty(name="idlefish.<comp>.mock", havingValue="false")`，生产通过环境变量关闭 Mock 后自动启用。
- 真实实现均为**零新增依赖**的自建 HTTP 客户端（`RestTemplate` + Jackson + JDK 原生加解密：HMAC-SHA1 / HMAC-SHA256 / RSA-SHA256 / AES-256-GCM），在离线 Maven 仓库（`.m2/repository`）约束下可编译，并具备签名、超时、重试、幂等、降级等生产级健壮性。

### 1.1 配置开关一览

| 组件 | 配置项 | 默认值 | Mock 实现 | 真实实现 |
| --- | --- | --- | --- | --- |
| 微信支付/分账 | `idlefish.pay.mock` | `true`（环境变量 `IDLEFISH_PAY_MOCK`） | `MockWechatEscrowServiceImpl` | `RealWechatEscrowServiceImpl` |
| 商品检索/索引 | `idlefish.search.mock` | `true` | `DbSearchServiceImpl` | `EsSearchServiceImpl` |
| 延时队列 | `idlefish.mq.mock` | `true` | `LocalDelayQueueServiceImpl` | `RocketMqDelayServiceImpl` |
| 内容审核 | `idlefish.audit.mock` | `true` | `MockContentAuditServiceImpl` | `RealContentAuditServiceImpl` |
| 物流轨迹 | `idlefish.logistics.mock` | `true` | `MockLogisticsServiceImpl` | `RealLogisticsServiceImpl` |
| 对象存储 | `idlefish.oss.mock` | `true`（缺失即本地盘） | `LocalDiskStorageServiceImpl` | `OssStorageServiceImpl` |

> 注意：`application.yml` 中仍保留 `idlefish.file.mock`（历史遗留），**实际存储开关以 `idlefish.oss.mock` 为准**（见 `LocalDiskStorageServiceImpl` 的 `matchIfMissing=true`）。生产接入 OSS 时请设置 `idlefish.oss.mock=false` 并填充 `idlefish.oss.*`，同时可删除 `idlefish.file.mock`。

## 2. 七大组件接入明细

### 2.1 ES 索引（模块 B2 / B5）
- **接口**：`SearchService`（`indexItem(Item)` / `removeItem(Long)`）
- **Mock（默认）**：`DbSearchServiceImpl` —— 索引/删除为空实现，检索回退到 DB `LIKE` 查询，保证链路可用。
- **真实（生产）**：`EsSearchServiceImpl` —— 启动时 `@PostConstruct` 自动建索引（`ik_max_word` 分词）；写入/删除走 ES REST `_doc`；查询走 `_search`。**任何网络/ES 异常均降级为空结果集，不影响主流程**。
- **调用点**：`ItemService.submitReview`（过审上架时 `indexItem`）、`ItemService.audit` 通过、`edit`（在售编辑）索引更新、`offShelf` / `delete` 时 `removeItem`。

### 2.2 RocketMQ 延时队列（模块 D6）
- **接口**：`DelayQueueService`（`submit(type,bizId,ext,delaySec)` / `scanAndExecute()`）
- **Mock（默认）**：`LocalDelayQueueServiceImpl` —— 任务持久化到 `t_delay_task`，`@Scheduled(fixedDelay=5s)` 扫描执行，状态机 `pending→processing→done/failed`，失败可重试，不丢任务。
- **真实（生产）**：`RocketMqDelayServiceImpl` —— 通过 HTTP 向阿里云 RocketMQ 延时消息接口投递；本地 `t_delay_task` 作兜底；`@Scheduled(fixedDelay=30s)` 补偿；提供 `/api/mq/consume` 供 Broker 推送消费（`WebConfig` 已放行）。
- **已接入的延时任务**：
  - `ORDER_CLOSE`：下单后 30 分钟未支付关单（提交点 `OrderService.createOrder`）。
  - `REMIND_SHIP`：支付成功后 72 小时未发货提醒（提交点 `PayService.applyPaid`）。
  - `ORDER_CONFIRM`：发货后 10 天自动确认收货（提交点 `OrderService.ship`）。
  - `SETTLE`：交易完成结算（`DelayHandlers.SettleHandler`）。
- `TradeScheduler` 的定时扫描作为安全网与精准延时双轨并存，二者均幂等。

### 2.3 OSS 对象存储（文件上传）
- **接口**：`StorageService`（`store` / `getAccessUrl` / `delete`）；`FileService` 委托该接口。
- **Mock（默认）**：`LocalDiskStorageServiceImpl` —— 文件落盘到 `uploads/` 目录，访问地址 `/uploads/<name>`。
- **真实（生产）**：`OssStorageServiceImpl` —— OSS V1 协议 `PutObject` / `DeleteObject`，HMAC-SHA1 签名，`Authorization: OSS <ak>:<sig>`。
- **调用点**：`FileController.upload` → `FileService` → `StorageService`。

### 2.4 真实微信支付与分账（模块 D2）
- **接口**：`FundEscrowService`（预下单 `prepay` / 查支付 `queryPaid` / 退款 `refund` / 分账 `profitShare` / 回调解密 `decryptNotify` / 验签 `verifySignature` / `verifyNotify`）。
- **Mock（默认）**：`MockWechatEscrowServiceImpl` —— 预下单返回演示 `prepay_id`；`/api/pay/mock/{payNo}` 手动完成支付；分账/退款返回成功占位。
- **真实（生产）**：`RealWechatEscrowServiceImpl` —— 微信支付 v3 全链路：
  - JSAPI 预下单（取买家 `openid`）+ 二次签名（`timeStamp/nonceStr/package/paySign`，`signType=RSA`）。
  - 支付结果通知：`PayService.notifyV3` 先验证 Broker 签名（`WECHATPAY2-SHA256-RSA2048`，基于平台证书 `idlefish.pay.platform-cert`），再 AES-256-GCM 解密 `resource`，最后幂等落地。
  - 分账：`profitsharing` API 调用（`SettlementService.onTradeSuccess` 在 `!payMock()` 时触发，异常吞掉不影响主流程）。
- **回调端点**：`POST /api/pay/notify/v3`（`WebConfig` 已放行鉴权）。

### 2.5 真实物流 API（模块 D5）
- **接口**：`LogisticService`（`createLogistics` / `persistShip` / `track`）
- **Mock（默认）**：`MockLogisticsServiceImpl` —— `persistShip` 落库 `t_logistics`（运单号 + 轨迹 JSON）；`track` 返回 3 条演示轨迹。
- **真实（生产）**：`RealLogisticsServiceImpl` —— 快递100 实时查询（MD5 签名 `sign=MD5(param+customer+key)`），**查询失败自动降级为 Mock 轨迹**，保证前端不空白。
- **调用点**：`OrderService.ship` / `adminShip` 发货 → `logisticService.persistShip(orderNo,no,"SF")`；`OrderController.GET /{orderNo}/logistics` → `logisticsTrack`。

### 2.6 AI 内容审核（模块 B3 / E3）
- **接口**：`ContentAuditService`（`audit(title,desc,images)` / `auditText(content)`），返回 `AuditResult(pass, reason)`。
- **Mock（默认）**：`MockContentAuditServiceImpl` —— 复用 `SensitiveWords` 关键词/正则机审（命中如「代开发票」「色情」「假币」等即拒绝）。
- **真实（生产）**：`RealContentAuditServiceImpl` —— 阿里云内容安全（绿网）ROA 协议，HMAC-SHA1 签名，文本/图片同步检测。
- **调用点**：
  - B3 商品发布：`ItemService.auditContent` → `contentAuditService.audit(title,desc,images)`；命中敏感词则商品进入 `rejected`。
  - E3 即时通讯：`ImService.send` → `contentAuditService.auditText(content)`，审核不通过则拒绝发送。

### 2.7 设备指纹风控规则库（模块 F3）
- **实体/表**：`t_device_fingerprint`（设备↔用户映射、`uk_device_user` 唯一约束）、`t_track_event`（新增 `device_id/ip/ua` 列与 `idx_track_device` 索引）。
- **服务**：`DeviceFingerprintService`（`record` / `countUsers` / `isNewDevice` / `isBlacklisted`）、`TrackService`（埋点同时落设备指纹）、`RiskEngine`（R1~R6 规则）：
  - R1 高频发布 / R2 退款滥用 / R3 新设备+高额 / R4 单设备多账号 / R5 设备下单频次 / R6 设备黑名单。
- **设备上下文**：`DeviceContext` + `DeviceContextInterceptor` 从请求头 `X-Device-Id` / `User-Agent` / `X-Forwarded-For` 提取，对所有 `/api/**` 生效。
- **开关**：`idlefish.risk.device-enabled=true` 时启用指纹采集与规则判定。

## 3. 生产切换速查（环境变量）

```bash
# 关闭各组件 Mock，启用真实实现（需同步配置对应密钥/端点）
export IDLEFISH_PAY_MOCK=false          # 真实微信支付 + 分账
export IDLEFISH_PAY_MCHID=...
export IDLEFISH_PAY_APPID=...
export IDLEFISH_PAY_SERIAL=...
export IDLEFISH_PAY_PRIVATE_KEY=...     # PEM 私钥
export IDLEFISH_PAY_APIV3_KEY=...       # APIv3 密钥（AES-256-GCM 解密）
export IDLEFISH_PAY_NOTIFY_URL=https://your-domain/api/pay/notify/v3

export IDLEFISH_OSS_MOCK=false          # 真实 OSS（注意是 oss.mock，非 file.mock）
export IDLEFISH_OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
export IDLEFISH_OSS_BUCKET=...
export IDLEFISH_OSS_AK=...
export IDLEFISH_OSS_SK=...

export IDLEFISH_MQ_MOCK=false           # 真实 RocketMQ 延时队列
export IDLEFISH_MQ_ENDPOINT=...
export IDLEFISH_MQ_AK=...
export IDLEFISH_MQ_SK=...
export IDLEFISH_MQ_INSTANCE=...

# search / audit / logistics 同理设置 idlefish.search.mock=false 等
```

> 真实实现均具备**网络异常降级 / 签名校验 / 幂等 / 超时**，可在缺网或缺配置时安全回退，不会阻塞主交易链路。

## 4. 联调验证结论

离线冒烟（`SubsystemSmokeTest` + 免 surefire 的 `SmokeRunner`）已跑通七大组件的端到端集成链路，全部断言通过：

| 验证项 | 结果 |
| --- | --- |
| 上下文加载（Bean 装配无冲突） | PASS |
| 商品发布→过审上架（ES 索引/Mock） | PASS |
| 下单提交 `ORDER_CLOSE` 延时任务（D6） | PASS |
| 设备指纹落库（F3） | PASS |
| 支付下单 `PayOrder` 创建（D2） | PASS |
| Mock 支付完成→订单 `paid`（D2 applyPaid） | PASS |
| 支付成功提交 `REMIND_SHIP` 延时任务（D6） | PASS |
| 发货→`shipping` + 提交 `ORDER_CONFIRM`（D5/D6） | PASS |
| 物流轨迹查询非空（D5） | PASS |
| 确认收货→`completed`（结算触发） | PASS |
| 敏感词发布→`rejected`（B3 机审） | PASS |
| 正常商品发布→`onsale`（B3） | PASS |
| 文件上传→`/uploads/` 落盘（OSS/Mock） | PASS |

> 运行方式：正式回归使用 `mvn test -Dtest=SubsystemSmokeTest`；沙箱离线（无 surefire/launcher）使用 `java com.idlefish.trade.integration.SmokeRunner`（需以离线 `.m2` 全量 jar 拼 classpath，排除冲突的 `slf4j-api/1.7.36`）。
