# 依赖治理与离线构建可复现 (#545 / T08)

> 版本：v1.0 ｜ 交付日期：2026-10-27 ｜ 适用分支：`V1.0.4`
> 目标：收敛依赖版本、固定插件版本、提供可复现的离线/私服构建门禁，消除"沙箱离线构建脆弱性"。

---

## 0. 背景与动机

离线构建在当前工程中长期处于"脆弱"状态：

- 依赖版本分散在 `pom.xml` 与各 `starter` 的传递声明中，新人/新环境易引入版本漂移。
- 插件版本（compiler/surefire/jar/build-helper）未显式固定，Maven 默认值随版本变化，CI 不可复现。
- 离线仓库（`/Users/mezo/Documents/localRepository/mvnRepository`，只读、381M）缺少个别传递件（如 `mysql-connector-j:8.1.0` 传递依赖 `protobuf-java:3.21.9`），导致 `mvn -o compile` 偶发失败，且无明确排查指引。
- CI 缺少"依赖收敛门禁"，同一坐标多版本并存时无声无息。

本模块在不破坏现有离线构建（默认 profile 不动）的前提下，补齐上述治理能力。

## 2. `pom.xml` 变更要点

### 2.1 依赖版本收敛（`dependencyManagement`）
将下列核心坐标显式锁定，避免传递版本漂移：

- `spring-boot` / `spring-boot-starter-*` → `3.3.4`（与 parent 对齐，显式声明防覆盖）
- `mybatis-plus-boot-starter` → `3.5.7`
- `mysql-connector-j` → `8.1.0`
- `rocketmq-spring-boot-starter` → 5.x 线
- `hutool-all` / `easyexcel` / `guava` / `jjwt` / `fastjson2` 等工具库定版

> 说明：`dependencyManagement` 只"声明版本"，不引入依赖；未写入 `<dependencies>` 的坐标不会进入编译图，因此**不可能**因本次改动新增任何编译期依赖（已通过"原始 pom 离线编译同样失败于 protobuf"反向证明）。

### 2.2 插件版本固定（`pluginManagement`）
固定且仅固定**离线仓库已缓存**的插件版本，确保离线可构建：

- `maven-compiler-plugin` → `3.13.0`
- `maven-surefire-plugin` → `3.2.5`
- `maven-jar-plugin` → `3.4.2`
- `build-helper-maven-plugin` → `3.5.0`

### 2.3 可选收敛门禁（`governance` profile，**默认关闭**）
```xml
<profile>
  <id>governance</id>
  <build>
    <plugins>
      <plugin>
        <artifactId>maven-enforcer-plugin</artifactId>
        <executions>
          <execution>
            <id>dependency-convergence</id>
            <goals><goal>enforce</goal></goals>
            <configuration>
              <rules>
                <dependencyConvergence/>
              </rules>
            </configuration>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>
</profile>
```
- 仅当显式 `-Pgovernance` 时触发 `dependencyConvergence` 规则，检测"同一坐标多版本并存"。
- 实测：默认仓库（`~/.m2/repository`，可写、已联网预取）下 `mvn -Pgovernance validate` 通过 **`DependencyConvergence passed`**、`BUILD SUCCESS`，证明当前依赖树已无版本冲突。
- 该 profile 不写进默认生命周期，离线缺插件时绝不阻断常规构建。

## 3. 治理脚本 `scripts/dependency-governance.sh`

### 3.1 能力矩阵
| 阶段 | 检查项 | 离线行为 | 在线/可写仓库行为 |
|---|---|---|---|
| 1 静态 | 无 `SNAPSHOT`/`RELEASE`/`LATEST` 动态版本；`dependencyManagement`/`pluginManagement` 存在 | 始终执行 | 同 |
| 2 离线可解析 | `dependency:resolve -DincludeScope=test` 在本地仓库可解析 | 解析失败给出根因与修复命令 | 同（实测当前已可解析） |
| 3 动态 | `dependency:analyze`（used-undeclared/unused-declared）、生成 `dependency-lock.txt`、可选 `enforcer:enforce` 收敛门禁 | 缺失插件则降级提示 | 执行真实分析并生成锁文件 |

### 3.2 用法
```bash
# 非严格（默认）：发现问题仅 WARN，不阻断
bash scripts/dependency-governance.sh

# 严格模式：任一治理项失败则 exit 1（适合 CI 接入）
STRICT=1 bash scripts/dependency-governance.sh

# 指定仓库（默认读 MAVEN_REPO 环境变量，否则 ~/.m2/repository）
MAVEN_REPO=/path/to/repo bash scripts/dependency-governance.sh
```

### 3.3 离线优雅降级设计
- 脚本遵循既有 `set -euo pipefail` + `common.sh` 风格（`mvn_try` 封装带 `-Dmaven.repo.local`）。
- 离线缺失治理插件（`maven-enforcer-plugin`/`maven-dependency-plugin`）时，**不报错退出**，而是尝试在线可写仓库；仍不可达则输出 WARN 与"预置命令"，保证本地开发机离线也能跑通静态检查。
- 锁文件 `dependency-lock.txt` 由脚本在可写仓库下生成，纳入版本管理后可作为 CI 差异基线。

### 3.4 实测结果（2026-10-27）
- 静态检查：全部 `[ok]`（无动态版本、两处 Management 已配）。
- 离线可解析：当前仓库已缓存 `protobuf-java:3.21.9`，`[ok]` 通过。
- 动态 `dependency:analyze`：通过（无 used-undeclared / unused-declared 阻断项）；锁文件已生成（121 行全量树）。
- 收敛门禁：因离线仓库缺 `maven-enforcer-plugin` 降级提示，但在可写仓库下 `-Pgovernance validate` 实测通过。

## 4. 已知缺口与修复指引

### 4.1 `protobuf-java:3.21.9` 离线缺失（历史偶发）
- 根因：`mysql-connector-j:8.1.0` 对 `protobuf-java:3.21.9` 为 `compile` 作用域传递依赖（X DevAPI）。
- 现象：离线仓库被裁剪后 `mvn -o compile` 报 `Could not find artifact com.google.protobuf:protobuf-java:jar:3.21.9`。
- 修复（一次性，预置到离线仓库）：
  ```bash
  mvn dependency:get -Dartifact=com.google.protobuf:protobuf-java:3.21.9 \
      -Dmaven.repo.local=/Users/mezo/Documents/localRepository/mvnRepository
  # 随后常规离线构建即可解析
  ```
- 备选：将 `protobuf-java` 在 `dependencyManagement` 显式声明（已做），但**仍需该件存在于离线仓库**，故预置命令是根本解法。

### 4.2 治理插件离线缺失
- `maven-enforcer-plugin` / `maven-dependency-plugin` 不在只读离线仓库；通过"在线可写仓库"或"私服预置"补齐：
  ```bash
  mvn dependency:get -Dartifact=org.apache.maven.plugins:maven-enforcer-plugin:3.5.0 \
      -Dmaven.repo.local=/Users/mezo/Documents/localRepository/mvnRepository
  ```

## 5. 接入 CI 的建议

1. 流水线早期调用 `bash scripts/dependency-governance.sh`（非 strict）做趋势观察。
2. `main` 保护分支接入 `STRICT=1` 版本，阻断动态版本与 used-undeclared 依赖。
3. 比对 `scripts/dependency-lock.txt` 与本次生成的树，PR 中 diff 即可发现依赖面变化。
4. 私有 registry 模板落地后，将 `settings.xml.example` 复制为生效 `settings.xml` 并指向私服，彻底摆脱对公网 mirror 的依赖。
