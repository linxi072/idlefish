
二手交易小程序 · P0 研发任务拆解与排期
依据：《需求池与优先级清单 V1.0》P0 共 26 项
技术栈： Java 17 + Spring Boot 3（单体，按领域分包；IM 用 Spring WebSocket/Java）；搜索 Elasticsearch（单节点）；异步 RocketMQ（单节点）；小程序原生 + Taro
版本： V1.2 · 单体化重排（含逐任务起止日期）  ｜ 状态：待技术负责人确认 ｜ 2026-09-17（启动日假设 2026-09-21，周一）
架构基准：《系统架构说明书 V2.0（单体化修订）》
────────────────────────────────────────
一、拆解原则
一个任务 = 一个可交付、可验收、可独立联调的单元 ，粒度控制在 2-5 人日。
每项任务标注  依赖项  与  联调方 ，避免"都等对方"的死锁。
优先打通  支付前主链路 （浏览 → 咨询 → 下单 → 支付），履约与售后紧随。
埋点与风控不后置——上线后补埋点等于数据永久缺失。

4.2 关键路径（最长依赖链，决定最早上线时间）
A1 鉴权/脚手架 → B1 类目 → B2 发布 → B4 状态机 → B5 详情/索引         → D1 下单 → D2 支付 → D6 超时任务 → D7 结算 → D8 售后 → 提审
