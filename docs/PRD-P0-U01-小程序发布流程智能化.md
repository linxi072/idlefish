## 一、背景与问题

当前卖家发布二手商品需**手工填写全部字段**：标题、描述、成色、类目、属性、价格、图片。实测痛点：

- **定价难**：二手商品无标准价，卖家不知该标多少 → 要么虚高无人问，要么贱卖亏本；反复改价耗时长。
- **描述难写**：多数卖家不愿写长描述，导致商品信息稀薄（仅标题+几张图）→ 买家不敢买、搜索召回差、审核风险高。
- **类目/属性选择繁琐**：三级类目 + 属性模板（如数码的「成色/内存/保修」）需逐项点选，路径长、易放弃。
- 结果：**发布完成率低**、商品质量差、后续转化与争议成本上升。

**行业趋势**：AI 生成式发布（拍照识别 → 自动生成标题/描述/类目/属性/估价）已成为二手与电商平台的标配体验（闲鱼「AI 帮我卖」等）。

---

## 二、目标与非目标

**目标（可度量）**
- G1：发布**完成率**提升 ≥ 20%（进入发布页 → 成功提交）。
- G2：单次发布**中位耗时下降 ≥ 40%**（基线取上线前 30 天埋点中位数）。
- G3：AI 生成描述的**采用率 ≥ 60%**（用户未大幅删改即提交）。
- G4：估价区间对最终成交价的**命中率 ≥ 70%**（成交价落在建议区间内）。
- G5：带完整属性/描述的**商品占比提升 ≥ 30%**。

**非目标**
- 不强制用户使用 AI（始终可手工编辑，AI 仅做预填）。
- 不改变商品数据结构与审核规则（仍走现有审核与风控关键词）。
- 不承诺估价即为成交价（明确为「建议区间」）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 新手卖家 | 作为第一次卖东西的用户，我希望拍张照就能自动生成标题、描述和价格，以便快速发布 |
| 高频卖家 | 作为经常出闲置的用户，我希望类目与属性自动带出，我只改关键项，以便批量发布 |
| 买家 | 作为买家，我希望商品信息完整（成色/瑕疵/属性），以便判断值不值得买 |
| 运营/审核 | 作为审核方，我希望描述完整度提升，以便降低违规与低质商品比例 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Event-driven | 当用户上传商品图片后，系统应自动识别品类并**预填建议类目**（可修改） |
| REQ-02 | Event-driven | 当图片识别完成时，系统应生成标题与描述草稿，并预填到对应输入框供用户编辑 |
| REQ-03 | Event-driven | 当类目确定后，系统应自动加载并预填该类目的属性模板（如成色/内存/保修） |
| REQ-04 | Event-driven | 当价格输入框获得焦点时，系统应基于品类、成色与历史成交给出**建议价格区间** |
| REQ-05 | Unwanted | 若 AI 服务超时或不可用，系统应降级为空表单 + 手动引导，**不得**阻塞发布 |
| REQ-06 | Unwanted | 若用户手工修改了 AI 生成内容，系统应保留用户修改值，**不得**在后续交互中覆盖 |
| REQ-07 | State-driven | 在图片上传中状态期间，系统应展示上传进度与失败重试入口 |
| REQ-08 | Event-driven | 当用户提交发布时，系统应校验必填项（标题/类目/价格/图片）并给出字段级错误提示 |
| REQ-09 | Ubiquitous | 系统应**始终**明示 AI 生成内容与估价仅供参考，最终信息由卖家负责确认 |
| REQ-10 | Optional | 若用户未上传图片，系统应提示「上传图片可获得智能定价与描述」但不强制 |
| REQ-11 | Event-driven | 当发布成功时，系统应引导至商品详情页并提示「预计曝光/同类成交参考」 |

## 五、流程说明

**主流程（AI 辅助发布）**
```
进入发布页 → 拍照/选图（OSS 上传，展示进度）
  → [REQ-01] 图片识别 → 建议类目（可改）
  → [REQ-03] 类目确定 → 自动加载属性模板并预填
  → [REQ-02] 生成标题/描述草稿（可编辑）
  → [REQ-04] 估价：给出建议区间（基于品类+成色+历史成交）
  → 用户确认/修改 → [REQ-08] 必填校验 → 提交 → 进入审核
  → [REQ-11] 发布成功页
```

**降级流程**：AI 不可用（REQ-05）→ 隐藏智能区块 → 纯手工填写 → 正常提交。

**异常流程**：上传失败（重试）、识别置信度低（不预填类目，仅提示）、估价无数据（不展示区间）。

## 六、交互说明

- **发布页分区**：① 图片区（最多 N 张，进度与重试）② 智能建议卡（类目/描述/估价，可「采用/忽略」）③ 属性区（按模板动态渲染）④ 价格区（输入框 + 建议区间气泡 + 「按建议填写」按钮）。
- **关键原则**：AI 结果**预填而非覆盖**，所有智能区块可一键清空；用户改过的值加「已修改」标记（REQ-06）。
- **信任提示**：描述区底部固定小字「内容由 AI 生成，请核对后发布」（REQ-09）。
- **失败态**：图片上传失败显示重试；AI 不可用静默降级，不弹错误打断用户。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 发布完成率 | 提交成功 / 进入发布页 | 提升 ≥ 20% |
| 发布中位耗时 | 进入 → 提交（分钟） | 下降 ≥ 40% |
| AI 描述采用率 | 未大幅删改即提交 / 生成总数 | ≥ 60% |
| 类目建议准确率 | 用户未修改类目 / 建议总数 | ≥ 75% |
| 估价命中率 | 成交价落在建议区间内 / 成交总数 | ≥ 70% |
| 信息完整度 | 含属性+描述 ≥ N 字的商品占比 | 提升 ≥ 30% |
| AI 不可用率 | AI 超时/失败 / 调用总数 | < 2% |

**埋点**：`publish_enter`、`image_upload_ok/fail`、`ai_suggest_return`、`ai_suggest_adopt`、`category_modified`、`price_suggest_shown/adopted`、`publish_submit_ok/fail`、`publish_duration`。

## 八、边界场景与异常状态

1. 图片模糊/多商品同框 → 识别置信度低 → 不预填类目，提示重拍。
2. 冷门类目无历史成交数据 → 不展示估价区间，仅给成色系数提示。
3. 用户连续重拍/换图 → 已填内容保留，仅刷新智能建议（不得清空用户输入）。
4. 属性模板含必填项（`required=1`）→ 未填则提交拦截。
5. 违规内容被 AI 生成（如夸大描述）→ 仍须过现有审核与风控关键词，命中即拦截。
6. 弱网/断网 → 草稿本地缓存，恢复后可继续。

---

## 九、权限与合规

- 用户图片上传至 OSS 前需明确授权；AI 生成内容不得包含虚假宣传或侵权表述。
- AI 生成与估价需明示「仅供参考」，避免构成价格承诺（合规风险）。
- 图片与描述仍须过现有内容审核与风控关键词，AI 不豁免审核。
- 用户数据用于模型训练需单独授权（默认不用于训练）。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | ITER-F03 AI 智能定价能力（估价接口） | U01 可先上「图片识别+描述生成」，估价随 F03 灰度 |
| 依赖 | OSS 图片上传、属性模板（`attrTemplates`）、成色字典 | 已具备，直接复用 |
| 依赖 | 历史成交数据（`analyticsCondition`）用于估价 | 冷启动阶段可用规则兜底 |
| 风险 | AI 生成违规/夸大描述引发合规问题 | 强制过现有审核 + 免责明示 |
| 风险 | 估价不准引发买卖纠纷 | 明示参考属性，最终定价权归卖家 |
| 风险 | 识别准确率低导致体验反而变差 | 低置信度不预填，仅提示；持续回流数据迭代 |
