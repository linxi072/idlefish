| 项 | 内容 |

## 一、背景与问题

F-14.5 已交付运营 BI，但当前形态是**「图表集合」而非「经营叙事」**：

- **有数据无结论**：运营打开 BI 看到一堆曲线，却不知道「今天该关注什么」，需要自己比对找异常。
- **缺少异常预警**：GMV 暴跌、退款率飙升、审核积压等异常靠人肉发现，往往滞后 1~2 天。
- **口径不统一**：不同页面对「GMV/成交额/活跃」的定义可能不一致，跨页比对引发信任危机。
- **无法下钻归因**：看到「今日 GMV 下降」后需要手动去订单/商品/活动页逐个排查，路径长。
- **管理层视角缺失**：管理者需要的是「一屏看懂经营状况 + 结论 + 建议动作」，而非原始图表。
- **移动端不可用**：管理层常在手机上看数，当前 BI 仅 PC 端。

**现有可复用资产**：echarts 已在 pc-admin 真实引入并有降级方案（`hasEcharts` 判断 + CSS 条形图），`analytics*` 接口族已提供数据；本项重在**组织方式、口径治理与预警**，而非从零建设图表能力。

---

## 二、目标与非目标

**目标（可度量）**
- G1：经营看板**首屏给出结论**：顶层「经营健康度 + 今日核心结论卡（≤3 条）」，管理层无需下钻即可判断。
- G2：异常**自动发现**：核心指标（GMV、订单、退款率、审核积压、支付成功率）异常**在 30 分钟内触发预警**。
- G3：指标口径**统一治理**：建立指标字典，同名指标在任何页面口径一致（口径不一致问题清零）。
- G4：支持**一键归因下钻**：从异常结论 → 维度拆分（品类/地区/时段/渠道）→ 明细列表，**点击 ≤ 3 次**。
- G5：预警**可订阅**：按角色推送（管理层日报、运营实时告警），支持退订（与 ITER-U05 合规一致）。
- G6：移动端可看：关键看板在手机浏览器可用（响应式，复用已建的响应式栅格）。

**非目标**
- 不做自助式 BI / 拖拽建表（成本过高，用户量不匹配）。
- 不做实时秒级看板（准实时 5~15 分钟足够，实时属 ITER-T01 范畴）。
- 不替代 F-14.5 运营 BI 明细页（本项是其上的「叙事层」）。
- 不做机器学习预测（仅同环比与阈值/统计基线预警）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 管理层 | 作为管理者，我希望一屏看到经营结论与风险，以便快速决策 |
| 运营 | 作为运营，我希望异常自动告警并可下钻定位，以便及时干预 |
| 数据 | 作为数据，我希望指标口径统一且可维护，以便减少解释成本 |
| 客服/风控 | 作为客服，我希望看到与自己相关的预警（工单积压/纠纷率），以便调配人力 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 系统应**始终**以指标字典为唯一口径来源，任何看板/页面引用同名指标必须口径一致 |
| REQ-02 | Ubiquitous | 涉及金额指标应以「分」为单位存储计算，展示时格式化为元并统一小数位 |
| REQ-03 | Event-driven | 当核心指标偏离基线（同环比或统计基线）超过阈值时，系统应生成异常事件并在 30 分钟内通知 |
| REQ-04 | Event-driven | 当异常事件生成时，系统应同时给出可能归因（维度贡献度 Top N），而非仅报警 |
| REQ-05 | State-driven | 在用户查看异常结论时，系统应支持下钻至维度拆分与明细列表（≤3 次点击） |
| REQ-06 | Unwanted | 若指标数据延迟或未就绪，系统应**显示数据时间与状态**，不得用过期数据冒充最新 |
| REQ-07 | Ubiquitous | 每个指标应可查看口径说明（定义、统计口径、数据来源、更新频率） |
| REQ-08 | Event-driven | 当用户订阅预警时，系统应按订阅规则推送（日报/实时/阈值），并支持一键退订 |
| REQ-09 | Unwanted | 若预警在短时间内重复触发同一异常，系统应**合并抑制**（避免告警风暴） |
| REQ-10 | Ubiquitous | 看板应响应式适配移动端（关键结论与趋势在小屏可读，明细下钻可弱化） |
| REQ-11 | Unwanted | 若 echarts 不可用，系统应降级为表格/简易图形，**不得**出现空白图表区 |
| REQ-12 | Ubiquitous | 看板应支持时间范围切换（今日/近 7 日/近 30 日/自定义）且各图表口径随之一致 |
| REQ-13 | Optional | 若用户需要对外汇报，系统应支持导出（CSV/图片）且导出含口径与数据时间 |
| REQ-14 | Ubiquitous | 异常结论与归因逻辑应可配置（阈值、基线算法、贡献度算法），变更需留痕 |

## 五、流程说明

**看板渲染流程**
```
选择时间范围（REQ-12）→ 加载核心指标（口径来自指标字典 REQ-01）
  → 计算同环比与基线偏离 → 生成异常结论卡（REQ-03/REQ-04）
  → 渲染：健康度 → 结论卡 → 趋势 → 维度拆分 → 明细入口
  → [数据未就绪 REQ-06] 显示数据时间与「计算中/延迟」状态
  → [echarts 不可用 REQ-11] 降级表格/条形图
```

**预警流程**
```
定时计算（准实时 5~15 分钟）
  → 阈值/统计基线比对 → [偏离] 生成异常事件
  → 归因（维度贡献度 Top N，REQ-04）
  → 抑制合并（REQ-09）→ 推送（按订阅 REQ-08）
  → 用户点击预警 → 直达看板对应下钻视图（REQ-05）
```

**归因流程**：异常结论 → 维度拆分（品类/地区/时段/渠道）→ 贡献度排序（对总偏离的贡献）→ 明细列表 → 定位具体对象。

## 六、交互说明

- **首屏结构（自上而下）**：
  1. 经营健康度（综合分/状态色）与数据更新时间（REQ-06）
  2. 核心指标卡（GMV、订单数、退款率、活跃、审核积压、支付成功率）含同环比
  3. **今日结论卡（≤3 条）**：「GMV 同比下降 18%，主要来自数码 3C（贡献 -12pp）」+「查看归因」按钮
  4. 趋势图（可切换指标）
  5. 维度拆分与 Top 榜（品类/地区/渠道）
- **口径说明**：指标名旁 `?` 悬浮展示口径卡片（REQ-07），含定义与更新频率。
- **异常归因抽屉**：点击结论 → 右侧抽屉展示维度贡献度（瀑布/条形）+ 明细表格 + 「导出」。
- **订阅中心**：按角色选择订阅指标、阈值、推送方式（站内/邮件/企微）、频率；一键退订（REQ-08）。
- **移动端**：结论卡 + 核心指标 + 趋势优先渲染，维度拆分折叠（REQ-10）。
- **PC 后台入口**：报表管理域新增「经营看板」，与「运营 BI」并列（BI 保留为明细分析页）。

## 七、数据口径与指标

| 指标 | 口径 | 目标/用途 |
|---|---|---|
| 口径一致率 | 同名指标口径一致数 / 总同名指标 | 100% |
| 异常发现时延 | 异常发生 → 预警触达 | ≤ 30 分钟 |
| 首屏结论有用率 | 用户调研中认为结论有用的占比 | ≥ 70% |
| 归因准确率 | 归因指向维度确为主要贡献的占比 | ≥ 75% |
| 下钻效率 | 从结论到定位明细的点击次数 | ≤ 3 次 |
| 告警抑制率 | 被合并的重复告警 / 原始告警 | ≥ 60%（避免风暴） |
| 看板加载时长 P95 | | ≤ 3 秒 |
| 订阅退订率 | 退订 / 订阅 | ≤ 5%（反映推送价值） |

**埋点**：`dashboard_view`、`dashboard_conclusion_click`、`dashboard_drill`、`alert_trigger`、`alert_suppress`、`alert_subscribe`、`metric_definition_view`。

## 八、边界场景与异常状态

1. **数据延迟**：ETL 未跑完 → 显示数据时间与「延迟」标记，不得静默展示昨日数据（REQ-06）。
2. **告警风暴**：一次故障触发数十条告警 → 抑制合并 + 按严重度排序（REQ-09）。
3. **归因误导**：贡献度算法在多因素叠加时可能误判 → 展示 Top N 并标注「可能归因」，不宣称确定因果。
4. **同环比失真**：节假日/大促导致同比异常 → 提供「对齐大促日」或排除特殊日的口径选项。
5. **小样本噪声**：新类目数据量小导致波动剧烈 → 最小样本阈值，不足时标注「样本不足不参与预警」。
6. **口径变更**：指标定义调整导致历史曲线跳变 → 版本化口径 + 变更公告 + 标注断点。
7. **echarts 加载失败**：降级表格/条形图（REQ-11），不得空白。
8. **移动端性能**：大量图表在小屏卡顿 → 移动端默认减少图表数量、按需加载。

## 九、权限与合规

- 看板数据属经营敏感信息 → RBAC 按角色限制可见范围（如区域机构仅看本区，配合 ITER-T05）。
- 导出功能需留痕（谁/何时/导出内容），防止数据外泄（REQ-13）。
- 预警推送须支持退订（REQ-08），退订后零下发（与 ITER-U05 一致）。
- 涉及用户级明细的查看需额外授权并留痕，禁止通过看板批量导出个人信息。
- 口径说明对外（如卖家侧）展示时不得泄露平台商业敏感信息。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | F-14.5 BI 的 `analytics*` 接口 | 复用现有数据源，本项做叙事层 |
| 依赖 | pc-admin 已引入 echarts 并有降级方案 | 复用降级逻辑，避免重复建设 |
| 依赖 | ITER-T01 可观测性指标（技术侧指标源） | 业务指标与技术指标分源，避免混淆 |
| 依赖 | ITER-T05（按机构看数的权限隔离） | 看板可见范围需配合数据权限 |
| 风险 | 口径不统一会摧毁看板可信度 | 先做指标字典治理，再上叙事层 |
| 风险 | 归因误判导致错误决策 | 标注「可能归因」，提供明细自查 |
| 风险 | 告警风暴引发疲劳与忽视 | 抑制合并 + 严重度分级 + 订阅可配 |
| 风险 | 准实时计算带来数据库压力 | 预聚合/离线计算，看板只读结果 |
| 风险 | 离线沙箱无真实数据 | 用 mock 数据验证渲染与降级，口径留本机/CI 校验 |
