# PRD｜ITER-T05 多租户与机构数据隔离深化

| 项 | 内容 |
|---|---|
| 编号 | ITER-T05 |
| 维度 / 优先级 | 技术架构演进 / **P1** |
| 状态 | 待评审 |
| 建议负责 | 后端负责人（权限/数据层） |
| 关联模块 | `Organization` 机构管理（已扁平为表格，含层级）、`Role` 角色管理（RBAC）、`SysUser` 管理员、F-16 MySQL+RBAC、ITER-F05（同城回收需区域机构模型） |
| 编制日期 | 2026-10-02 |

---

## 一、背景与问题

系统已具备基础的**功能权限**（RBAC：角色 → 菜单/接口），以及 `Organization` 机构层级（总部 → 区域中心 → 分部，可配负责人/电话/状态）。

**缺失的是「数据权限」**：
1. 当前管理员登录后**可见全量数据**，无法按所属机构收口 —— 区域运营能看到其他区域的订单、用户、资金数据。
2. `Organization` 目前主要是**组织架构展示**（树/表格 CRUD），**未与业务数据建立归属关系**，也未参与查询过滤。
3. 随着 ITER-F05（同城回收、区域履约）推进，区域化运营将成为刚需 —— 若不先建数据隔离，后续每个区域相关功能都要各自打补丁，形成权限烟囱。
4. 多区域/合作商户场景下存在**越权风险**与合规隐患（最小必要原则）。

---

## 二、目标与非目标

**目标（可度量）**
- G1：管理员仅可见**其机构及下属机构**范围内的数据（订单/用户/商品/资金/工单），越权访问测试**全部拦截**。
- G2：数据权限规则**集中可配**（按角色 × 数据范围），新增业务模块按统一切面接入，**不散落各 Service**。
- G3：`Organization` 与业务数据建立归属字段，支持按机构维度统计与导出。
- G4：隔离逻辑**有自动化测试覆盖**（单测 + 越权用例），防止后续重构击穿。

**非目标**
- 不做完整 SaaS 多租户（独立库/独立 schema），本项为**同库行级隔离**。
- 不重构现有 RBAC 功能权限模型（在其上叠加数据权限）。
- 不改变现有机构 CRUD 的交互（已扁平为表格）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 区域运营 | 作为区域运营，我希望只看到本区域的订单与用户，以便专注本地业务 |
| 总部管理员 | 作为总部管理员，我希望可跨区域查看，以便全局管理与对账 |
| 安全/合规 | 作为合规方，我希望数据访问遵循最小必要原则，越权可被审计 |
| 后端 | 作为后端，我希望数据权限集中配置，新模块不必各自实现过滤逻辑 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 系统应**始终**按当前登录用户的机构范围过滤业务数据查询（订单/用户/商品/资金/工单） |
| REQ-02 | Ubiquitous | 系统应**始终**支持四种数据范围：`仅本机构` / `本机构及下级` / `指定机构` / `全部`，可按角色配置 |
| REQ-03 | Event-driven | 当管理员执行跨机构数据访问时，系统应拒绝并返回明确的权限不足提示，且记录审计日志 |
| REQ-04 | Event-driven | 当业务数据创建时，系统应根据操作人自动写入归属机构字段 |
| REQ-05 | Unwanted | 若用户所属机构被停用或变更，系统应在下次访问时按新范围生效，**不得**沿用旧权限 |
| REQ-06 | State-driven | 在机构处于「停用」状态期间，该机构下管理员不得登录或访问任何业务数据 |
| REQ-07 | Event-driven | 当导出/下载数据时，导出范围应同样受数据权限约束，不得导出越权数据 |
| REQ-08 | Ubiquitous | 数据权限过滤应在**统一层面**实现（如拦截器/切面 + MyBatis 插件），不得散落于各业务 Service 手工拼接 |
| REQ-09 | Unwanted | 若某查询未声明数据范围归属，系统应默认按「仅本机构」从严处理，而非放行全量 |
| REQ-10 | Event-driven | 当机构层级调整（合并/迁移）时，系统应支持数据归属批量迁移且保留审计记录 |
| REQ-11 | Optional | 若需临时跨区域协作，应支持「临时授权」（带有效期），到期自动回收 |

## 五、流程说明

**鉴权与过滤流程**
```
用户登录 → 解析角色（功能权限）+ 数据范围（REQ-02）
  → 业务查询 → 统一数据权限切面自动注入机构过滤条件（REQ-08）
  → 返回结果（仅范围内数据）
  → 越权访问尝试 → 拦截 + 审计日志（REQ-03）
```

**归属写入流程**：业务数据创建 → 取操作人机构 → 写入归属字段（REQ-04）。

**机构变更流程**：停用（REQ-06）/ 迁移（REQ-10）→ 批量更新归属 + 审计 → 权限即时生效（REQ-05）。

---

## 六、交互说明

- **PC 后台 · 角色管理**：新增「数据范围」配置项（四种，REQ-02），与菜单权限并列。
- **PC 后台 · 机构管理**：现有扁平表格基础上，增加「数据归属迁移」「停用」操作；停用后该机构管理员不可登录。
- **业务列表页**：区域运营仅见本区域数据；页面可显示当前数据范围提示（如「当前范围：华东运营中心及下级」）。
- **导出**：导出按钮遵循数据范围，导出记录含操作人与范围（审计）。
- **临时授权**（REQ-11）：角色管理页可申请，带有效期，到期自动失效并在列表标注。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 越权拦截率 | 越权访问被拦截 / 越权尝试 | 100% |
| 过滤覆盖模块 | 接入数据权限的业务模块数 | 覆盖订单/用户/商品/资金/工单 |
| 归属字段完整率 | 有机构归属的业务数据占比 | 100%（存量需回填） |
| 自动化测试覆盖 | 数据权限单测 + 越权用例 | 覆盖四种范围 × 关键模块 |
| 权限生效时延 | 机构变更 → 权限生效 | 即时（下次访问生效） |
| 导出越权事故 | 导出越权数据事件数 | 0 |

## 八、边界场景与异常状态

1. **存量数据无归属** → 需一次性回填（按创建人机构/默认总部），否则按 REQ-09 从严会导致数据不可见。
2. **跨机构交易**（买家 A 区域、卖家 B 区域）→ 需明确订单归属规则（建议按卖家归属 + 双方所在机构均可见）。
3. **机构合并/拆分** → 数据迁移需事务与审计（REQ-10）。
4. **超级管理员** → 需保留「全部」范围，但操作需审计。
5. **缓存污染** → 权限相关缓存需按用户/机构维度隔离，避免 A 用户读到 B 用户范围数据。
6. **未声明归属的新模块** → 默认从严（REQ-09），避免新功能上线即越权。

---

## 九、权限与合规

- 遵循**最小必要原则**：默认仅本机构，显式配置才可扩大范围。
- 越权访问与跨机构导出需**审计留痕**（谁/何时/访问范围/操作），满足合规审计要求。
- 机构停用后管理员不得登录（REQ-06），避免离职人员残留访问。
- 临时授权需审批与有效期，到期自动回收（REQ-11）。

## 十、验收标准（可勾选）

- [ ] 管理员仅见本机构及下级数据（REQ-01）。
- [ ] 四种数据范围可按角色配置（REQ-02）。
- [ ] 越权访问被拦截并记录审计日志（REQ-03）。
- [ ] 业务数据创建自动写入归属机构（REQ-04）。
- [ ] 机构变更后权限即时生效，不沿用旧权限（REQ-05）。
- [ ] 停用机构管理员不可登录/访问（REQ-06）。
- [ ] 导出受数据范围约束（REQ-07）。
- [ ] 过滤逻辑集中在统一层面，非各 Service 手工拼接（REQ-08）。
- [ ] 未声明归属的查询默认从严（REQ-09）。
- [ ] 机构层级调整支持数据迁移且留痕（REQ-10）。
- [ ] 存量数据归属回填完成。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | `Organization` 机构模型、RBAC 角色管理（已具备） | 在其上扩展数据范围配置 |
| 依赖 | ITER-F05（区域履约）需要本项的区域机构能力 | 本项先行，为 F05 打样 |
| 风险 | 存量数据无归属，回填工作量大 | 按创建人机构回填，缺失归总部；回填脚本需可回滚 |
| 风险 | 切面改造影响面广，可能引发查询性能或误过滤 | 灰度模块接入 + 全量回归 + 越权用例自动化 |
| 风险 | 缓存未按用户/机构隔离导致数据串扰 | 缓存 key 纳入机构维度，专项测试 |
| 风险 | 跨机构交易归属规则不明确引发争议 | 明确规则：按卖家归属，双方机构均可见，写入 PRD 附录 |
