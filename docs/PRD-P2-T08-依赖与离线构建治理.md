## 一、背景与问题

项目当前存在**两套依赖生态**且都暴露了脆弱性：

**后端（Maven）**
- 离线构建依赖个人机器的 `.m2` 缓存：`mvn -o` 能否成功取决于缓存里恰好有哪些 jar，**换机/换 CI 就可能失败**（历史已出现 mysql-connector、redis/lettuce 的缓存问题）。
- `micrometer` 走可选 profile（build-helper 独立源码根），默认 `mvn -o` 不编译——这是**为迁就离线构建而牺牲可观测性**的妥协（ITER-T01 要改掉它，前提是依赖先治理）。
- 依赖版本无统一管理与定期升级机制，安全漏洞修复靠人工发现。

**前端（pc-admin，npm）**
- 已迁移到 Vite + npm，但历史出现过：`vue-router` 未声明导致无法解析、`package-lock.json` 指向 npmjs.org 导致 `npm install` 卡死——**网络可达性直接决定能否开发**。
- 新增 `@element-plus/icons-vue` 后锁文件需本机补全，存在「我这边能装你那边不能」的风险。

**共同问题**：构建**不可复现**、**不可离线**，既拖慢开发也阻断 CI 门禁（ITER-T03）与内网部署（ITER-T07）。

## 二、目标与非目标

**目标（可度量）**
- G1：**全新环境**（无 `.m2`、无 npm 缓存）在有私有仓库的网络下，`mvn -o`/`npm ci` **一次成功**，成功率 100%。
- G2：构建**可复现**：同一提交 SHA 两次构建产物一致（校验和可比）。
- G3：依赖版本**集中管理**（Maven BOM/dependencyManagement + npm 精确版本/lockfile），无散落版本声明。
- G4：依赖升级**自动化**：Renovate/Dependabot 定期提 PR，安全漏洞**高危 7 日内修复**。
- G5：`micrometer` 依赖入私有仓库后，具备**移出可选 profile** 的前提条件（配合 ITER-T01）。
- G6：锁文件与私有仓库完整性纳入 CI 校验（锁文件缺失/指向外网 → 阻断）。

**非目标**
- 不升级大版本框架（如 Spring Boot 4 / Vue 4）作为本项范围（升级单独立项）。
- 不引入 Monorepo 工具链（当前后端 + pc-admin + 小程序各自独立足够）。
- 不改变业务代码（仅构建与依赖层改造）。
- 不做开源镜像站的全量自建（用代理/缓存型私有仓库即可）。

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 后端应**始终**通过私有 Maven 仓库（代理 + 缓存）解析依赖，构建配置指向私服而非公共中央仓库 |
| REQ-02 | Ubiquitous | 前端应**始终**通过私有 npm registry（或国内镜像）安装，锁文件中的 `resolved` 指向私有源 |
| REQ-03 | Unwanted | 若锁文件缺失或与 `package.json` 不一致，CI 应**阻断**并要求重新生成 |
| REQ-04 | Ubiquitous | 依赖版本应集中声明（Maven `dependencyManagement`/BOM；npm 精确版本 + 单一 lockfile），禁止在多模块散落硬编码版本 |
| REQ-05 | Event-driven | 当依赖存在已知高危漏洞时，系统应自动生成升级 PR 并标记优先级 |
| REQ-06 | Unwanted | 若升级 PR 的构建或测试失败，CI 应**阻断**合入（不得带病升级） |
| REQ-07 | Ubiquitous | 构建应可复现：同一提交 SHA 的产物校验和一致（固定基础镜像、固定插件版本、禁用 SNAPSHOT 外部依赖） |
| REQ-08 | Event-driven | 当私有仓库缺失某依赖时，应自动代理拉取并缓存，后续构建命中缓存 |
| REQ-09 | Ubiquitous | 后端 `mvn -o` 离线构建应在 CI 中有专门校验任务（干净环境） |
| REQ-10 | Unwanted | 若构建意外访问公网中央仓库/registry，流水线应**告警**（表明私服未覆盖全量依赖） |
| REQ-11 | Ubiquitous | micrometer 及其传递依赖应纳入私有仓库，为移出可选 profile 提供前提 |
| REQ-12 | Optional | 若构建耗时超阈值，应启用构建缓存（Maven 本地仓库层缓存 / npm 缓存层）加速 |
| REQ-13 | Ubiquitous | 依赖清单（含版本与许可）应可导出，供安全与合规审计 |
| REQ-14 | Event-driven | 当新增依赖时，流水线应校验其许可协议（License）不违反合规要求 |

## 五、流程说明

**私有仓库接入（后端）**
```
配置 settings.xml 指向私服（mirrorOf central）
  → 首次构建：私服代理拉取并缓存（REQ-08）
  → 后续构建：命中缓存，可离线（mvn -o）
  → CI 干净环境校验（REQ-09）
```

**私有仓库接入（前端）**
```
.npmrc 指向私有 registry → npm ci（严格按 lockfile）
  → [lockfile 缺失/不一致 → REQ-03] 阻断
  → 锁文件 resolved 全指向私服（REQ-02）
```

**依赖升级流程**
```
Renovate 定期扫描 → [有更新/有漏洞] 生成 PR（REQ-05）
  → CI 编译 + 单测 + 契约测试（REQ-06 卡口）
  → 通过后人工评审合入 → 锁文件更新
```

**可复现校验**：同一 SHA 构建两次 → 比对产物校验和（REQ-07）→ 不一致则告警（常见于插件版本漂移、时间戳打入产物）。

## 六、交互说明

- **开发者侧**：提供一键初始化脚本（写 `settings.xml` / `.npmrc`、校验工具链版本），新人 10 分钟内可构建。
- **CI 视图**：构建任务分「在线构建」「离线构建（`mvn -o`）」「前端 `npm ci`」三类，各自状态可视；离线失败单独标记（这是本项核心门禁）。
- **依赖看板**：依赖清单（名称/版本/最新可用/漏洞等级/许可）、待处理升级 PR 列表。
- **告警**：私服未覆盖依赖（触发公网访问 REQ-10）、高危漏洞新增、锁文件不一致。
- **文档**：在 README/构建文档中固化「私有仓库地址 + 初始化步骤 + 常见故障排查」（历史多次因网络/锁文件卡住）。

## 八、边界场景与异常状态

1. **私服不可用**：代理型私服依赖上游可达 → 需缓存足够完整；私服宕机时构建应给出明确错误而非长时间卡死（历史卡死体验极差）。
2. **SNAPSHOT 依赖**：可复现性杀手 → 内部模块用固定版本发布，禁用外部 SNAPSHOT（REQ-07）。
3. **锁文件平台差异**：不同 OS 下载的 optional 二进制不同 → lockfile 需包含平台无关解析，或统一构建环境（容器化构建）。
4. **传递依赖漂移**：未锁定传递依赖版本导致行为变化 → Maven 用 dependencyManagement 收敛，npm 依赖 lockfile。
5. **插件版本未固定**：Maven 插件未锁版本会拉最新 → 显式声明插件版本（可复现前提）。
6. **内网完全隔离环境**：无法代理上游 → 需离线仓库导入机制（预先同步依赖包）。
7. **micrometer 可选 profile**：依赖未入私服前移出会破坏离线构建 → 必须先满足 REQ-11 再做 ITER-T01 的切换。
8. **多语言多仓库**：后端 Maven + 前端 npm + 小程序（无构建）→ 治理策略需覆盖 Maven 与 npm 两套，不可只做一半。

## 九、权限与合规

- 私有仓库写入需授权（防止投毒依赖），发布内部构件需审批并留痕。
- 依赖许可（License）需合规审查，禁止引入与项目许可冲突的依赖（REQ-14）。
- 依赖漏洞修复涉及生产变更，需走常规发布流程。
- 私有仓库的访问密钥不得入库，走 CI Secret 管理（与 ITER-T07 REQ-11 一致）。
- 依赖清单导出用于合规审计时，需包含版本与许可信息（REQ-13）。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | 需私有仓库基础设施（Nexus/Artifactory 或云厂商制品库） | 优先用云厂商托管制品库，降低自建运维成本 |
| 依赖 | ITER-T01（micrometer 常开依赖本项 REQ-11） | 顺序：先依赖入私服 → 再移出可选 profile |
| 依赖 | ITER-T03（CI 门禁需可复现构建） | 本项是门禁可信的前提 |
| 依赖 | ITER-T07（内网构建） | 共用同一套私服策略 |
| 风险 | 私服缓存不完整导致首次构建仍走公网 | 全量构建一次预热 + 公网访问告警（REQ-10） |
| 风险 | 依赖升级引发回归（尤其 MyBatis-Plus/Spring 小版本） | 升级 PR 必须过单测 + 契约测试（REQ-06） |
| 风险 | 锁文件再生引发大规模 diff | 仅在依赖变更时更新，禁止随手 `npm install` 提交 |
| 风险 | 内网完全隔离环境无法代理 | 预留离线导入通道（预先打包依赖） |
| 风险 | 沙箱环境无网络，无法验证私服 | 以「干净环境 `mvn -o`」为验收口径，验证留 CI/本机 |
