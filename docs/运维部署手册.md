# 闲置集 C2C 平台 · 运维部署手册

> 适用范围：闲置集二手交易小程序 **V1.0.3** 分支（仓库内含 `idlefish-backend` 后端 + `miniprogram` 微信小程序 + `pc-admin` PC 运营后台三大功能域）。
> 配套文档：`docs/真机联调验证手册.md`（联调验收口径）、`idlefish-backend/docs/后续功能迭代路线图.md`（功能规划）。
> 本文聚焦**生产/准生产环境的构建、配置、部署、监控与回滚**，区别于联调验证手册。

---

## 0. 系统架构与组件

| 功能域 | 技术栈 | 说明 |
|---|---|---|
| 后端 `idlefish-backend` | Spring Boot 3.3.4 / Java 17 / MyBatis-Plus 3.5.7 / jjwt 0.12.6 / MySQL 8.1.0 / WebSocket（spring-websocket）/ Redis（prod） | 单体，按领域分包（user/item/trade/marketing/notify/im/risk/system…）；外部组件（微信登录/支付/OSS/ES/RocketMQ/物流/内容安全）均 Mock/Real 可切换 |
| 小程序 `miniprogram` | 微信原生小程序 | `app.js` 的 `globalData.apiBaseUrl` + `useMock` 控制走 Mock 还是真实后端；IM 走 `ws(s)://<apiBaseUrl>/ws/im` |
| PC 后台 `pc-admin` | Vue3 + Element Plus（CDN 免构建） | 纯静态，无打包步骤；`src/api.js` 的 `USE_MOCK` + `BASE` 控制数据源；`start.sh` 或任意静态服务器托管 |

> 当前 `pom.xml` **未引入 actuator**。如需 K8s 探针/健康端点，建议新增 `spring-boot-starter-actuator` 并暴露 `/actuator/health`；下文 §5.4 给出无 actuator 时的替代探针方案。

## 2. 配置与 Profile 体系

### 2.1 构建 Profile

| Profile | 激活方式 | 行为 |
|---|---|---|
| `local`（默认） | `mvn -o -Plocal`（或省略，默认激活） | 编译时**排除** `RedisCacheServiceImpl`/`RedisCacheAutoConfig`（因离线缺 `spring-data-redis`），缓存走内存；`idlefish.cache.type=local` |
| `prod` | `mvn -Pprod`（需联网） | 引入 `spring-boot-starter-data-redis`；配合 `application-prod.yml` 将 `idlefish.cache.type=redis` |

> H2 内存库已彻底移除，**任何环境运行都需自备 MySQL 实例**。

### 2.2 数据源与缓存

- 数据源：`application.yml` 默认指向 `jdbc:mysql://127.0.0.1:3306/idlefish`（用户名/密码 `root/root`，**生产务必改**）。
- SQL 自动初始化：`spring.sql.init.mode=always`，应用启动时会自动执行 `schema-mysql.sql`（建表）+ `data-mysql.sql`（种子，含优惠券/类目/商品/管理员等），DDL/DML 均采用 `IF NOT EXISTS` / `INSERT IGNORE` **幂等**。
  - ⚠️ **只需手工创建空库 `idlefish`**（`CREATE DATABASE idlefish CHARACTER SET utf8mb4`），表与种子由 Spring 在首次启动自动灌入；重复启动不重复插入。
- 缓存：`idlefish.cache.type=local`（内存，local profile）/ `redis`（prod profile，`application-prod.yml` 指定 `host/port/database/password/timeout-ms`）。

### 2.3 业务配置与环境变量总表

所有敏感/环境相关配置均支持下划线环境变量注入（`${ENV:默认值}`），**生产务必通过环境变量注入，切勿明文提交**。

| 配置项（yml 路径） | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `idlefish.jwt.secret` | `JWT_SECRET` | 内置 DEV 默认密钥 | **生产必须替换为 ≥32 字节高强度密钥**；使用默认密钥启动时 `JwtUtil` 输出 `SECURITY WARN` |
| `idlefish.cookie.secure` | `IDLEFISH_COOKIE_SECURE` | `false` | HTTPS 生产环境置 `true`（F-04 JWT→Cookie） |
| `idlefish.ratelimit.enabled` | `IDLEFISH_RATELIMIT_ENABLED` | `false` | 请求限流骨架（固定窗口，按 clientIp:path）；生产按需开启 |
| `idlefish.login.mock` | `IDLEFISH_LOGIN_MOCK` | `true` | `true`=本地 Mock 登录（code 当 openid）；`false`=真实微信 `jscode2session` |
| `idlefish.login.appid` / `secret` | `IDLEFISH_LOGIN_APPID` / `IDLEFISH_LOGIN_SECRET` | 空 | 真实微信登录 AppID/AppSecret |
| `idlefish.pay.mock` | `IDLEFISH_PAY_MOCK` | `true` | `true`=本地 Mock 支付；`false`=对接真实微信支付分账 |
| `idlefish.pay.mchid/appid/serial-no/private-key/api-v3-key/notify-url` | `IDLEFISH_PAY_MCHID` / `APPID` / `SERIAL` / `PRIVATE_KEY` / `APIV3_KEY` / `NOTIFY_URL` | 空 | 真实支付凭据；`notify-url` 为回调地址（`/api/pay/notify` 已鉴权放行） |
| `idlefish.search.mock` | — | `true` | `true`=基于数据库模拟 ES；`false`=真实 Elasticsearch（`hosts`） |
| `idlefish.mq.mock` | `IDLEFISH_MQ_*` | `true` | `true`=DB+定时器本地延时；`false`=真实 RocketMQ |
| `idlefish.audit.mock` | — | `true` | `true`=本地关键词机审；`false`=阿里云内容安全 |
| `idlefish.logistics.mock` | `IDLEFISH_LOGI_*` | `true` | `true`=本地模拟轨迹；`false`=快递100/菜鸟 |
| `idlefish.file.mock` | — | `false` | `false`=真实落盘本地 `uploads/`（演示）；生产建议改 OSS |
| `idlefish.oss.*` | `IDLEFISH_OSS_*` | 空 | 对象存储凭据；生产文件存储建议接入 |
| `idlefish.notify.sms-mode` | `IDLEFISH_NOTIFY_SMS_MODE` | `mock` | `mock`=仅日志；`real`=真实短信（需 `sms.*` 凭据） |
| `idlefish.notify.push-enabled` | `IDLEFISH_NOTIFY_PUSH_ENABLED` | `true` | 实时 WebSocket 推送（本地 WS 即真实通道） |
| `idlefish.risk.*` | — | 设备指纹开 / 高额 5000000 分 | 风控阈值（设备数/订单速率/黑名单） |
| `idlefish.credit.*` | — | 权重见 yml | 信用评分权重，可覆盖 |

### 2.4 密钥与安全要点

- **JWT 密钥**：默认 DEV 密钥仅用于联调；生产通过 `JWT_SECRET` 注入高强度值，否则日志持续告警。
- **Cookie**：`secure` 在 HTTPS 下必须 `true`，配合 `SameSite` 防 CSRF（F-04）。
- **支付防伪造**：`PayService.notify` 幂等 + 金额校验 + v3 验签（金额不符/重复回调均拒绝，资损护栏）。
- **密码/凭据**：管理员密码 BCrypt 存储；所有第三方密钥走环境变量，禁止入库/入库前脱敏。

## 3. 数据库初始化

```bash
# 1) 仅创建空库（表与种子由应用启动自动执行）
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS idlefish CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"

# 2) 如需手工预置（可选，等效于 spring.sql.init 自动执行）
mysql -uroot -p idlefish < idlefish-backend/src/main/resources/db/schema-mysql.sql
mysql -uroot -p idlefish < idlefish-backend/src/main/resources/db/data-mysql.sql
```

> 若关闭自动初始化（`spring.sql.init.mode=never`），则必须手工执行上述两步；生产建议保留 `always` 并确保 `INSERT IGNORE` 幂等，便于版本升级自动补表。

## 4. 后端构建与部署

### 4.1 本地 / 联调（离线安全）

```bash
cd idlefish-backend
mvn -o -Plocal clean package -DskipTests          # 离线，不含 Redis 实现
java -jar target/idlefish-backend-1.0.0.jar --spring.profiles.active=local
```

### 4.2 生产构建（联网，启用 Redis）

```bash
cd idlefish-backend
mvn -Pprod clean package -DskipTests               # 联网拉取 spring-data-redis
java -jar target/idlefish-backend-1.0.0.jar \
  --spring.profiles.active=prod \
  -DJWT_SECRET='<>=32字节高强度密钥' \
  -DIDLEFISH_LOGIN_MOCK=false -DIDLEFISH_LOGIN_APPID=xxx -DIDLEFISH_LOGIN_SECRET=xxx \
  -DIDLEFISH_PAY_MOCK=false -DIDLEFISH_PAY_MCHID=xxx -DIDLEFISH_PAY_APPID=xxx \
  -DIDLEFISH_PAY_SERIAL=xxx -DIDLEFISH_PAY_PRIVATE_KEY=xxx -DIDLEFISH_PAY_APIV3_KEY=xxx \
  -DIDLEFISH_PAY_NOTIFY_URL=https://api.yourdomain.com/api/pay/notify \
  -DIDLEFISH_COOKIE_SECURE=true -DIDLEFISH_RATELIMIT_ENABLED=true
```

### 4.3 启动与 JVM 建议

- 端口：`server.port=8080`，`context-path=/`。
- JVM 建议：`-Xms512m -Xmx1024m -XX:+UseG1GC`（按实例规格调整）；日志默认控制台，生产建议重定向到文件 + 日志轮转（logback）。
- 后台运行：`nohup java -jar ... > app.log 2>&1 &` 或 systemd / Docker / K8s。

### 4.4 健康检查与探针（无 actuator 时）

- **应用存活**：`GET /api/health`（若已实现）或任意轻量接口；无 actuator 时可用 `curl http://localhost:8080/` 探活，或临时引入 `spring-boot-starter-actuator` 暴露 `/actuator/health`。
- **数据库就绪**：应用启动即执行 `spring.sql.init`；若库未建会启动失败，需在探针前保证 `idlefish` 库存在。
- **Redis 就绪**（prod）：`redis-cli -h <host> ping` 应为 `PONG`。

## 5. Redis 缓存（prod 专属）

- 仅 `prod` 构建 + `application-prod.yml` 的 `idlefish.cache.type=redis` 启用；`local` 构建不编译 Redis 实现。
- 连接：`idlefish.redis.host/port/database/password/timeout-ms`（均可在 yml 直接改，暂无独立环境变量，生产建议也外置）。
- 缓存键空间：`CacheService` 抽象（`LocalCacheServiceImpl` / `RedisCacheServiceImpl`），被用于字典、类目、系统权限等；释放/失效走 best-effort，缓存不可用不阻断主流程。
- 运维：Redis 宕机时若强行启用 `type=redis` 会抛连接异常 → 降级回 `local` 或保障 Redis 高可用（哨兵/集群）。

## 6. 小程序部署

### 6.1 开发者工具与配置

1. 微信开发者工具「导入项目」选择 `miniprogram/` 目录，填写小程序 AppID。
2. 修改 `miniprogram/app.js`：`globalData.apiBaseUrl`（后端地址）、`globalData.useMock`（联调 `false` 走真实后端，演示 `true` 用本地 Mock）。
3. 预览/真机调试：`useMock=false` 且 `apiBaseUrl` 为手机可访问的局域网 IP（如 `http://192.168.x.x:8080`）。

### 6.2 合法域名（公众号/小程序后台）

真机联网需在小程序后台配置：
- **request 合法域名**：`https://api.yourdomain.com`
- **socket 合法域名**：`wss://api.yourdomain.com`（IM 实时）
- **uploadFile / downloadFile 合法域名**：文件上传域名（若启用真实 OSS）

> 本地联调可在开发者工具勾选「不校验合法域名」临时绕过。

### 6.3 微信支付（JSAPI）

- 真实支付依赖 **F-01 真实登录**（`openid` 来自 `jscode2session`）与 **F-13 真实支付凭据**（`IDLEFISH_PAY_*`）。
- 支付回调地址 `notify-url` 须与微信商户平台配置一致，且 `/api/pay/notify`、`/api/pay/notify/v3` 已鉴权放行。

## 7. PC 运营后台部署

### 7.1 静态托管（免构建）

```bash
cd pc-admin
./start.sh                 # 内置静态服务器
# 或：python3 -m http.server 8787
```
浏览器打开 `http://localhost:8787`。默认 `USE_MOCK=true` 完整体验；真实联调将 `src/api.js` 的 `USE_MOCK` 改 `false` 并设 `BASE` 为后端地址。

### 7.2 反向代理（Nginx 推荐）

生产建议用 Nginx 统一收敛前端 + API，解决跨域与 HTTPS：

```nginx
server {
  listen 443 ssl;
  server_name admin.yourdomain.com;
  ssl_certificate     /path/fullchain.pem;
  ssl_certificate_key /path/privkey.pem;

  # PC 后台静态资源
  location / {
    root /var/www/pc-admin;
    index index.html;
    try_files $uri $uri/ /index.html;
  }
  # 后端 API 反代（解决跨域 + 鉴权统一）
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Authorization $http_authorization;
  }
  # IM WebSocket 反代
  location /ws/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

### 7.3 跨域

后端 `WebConfig` 已对 `/api/pay/**` 放行；若前端直连后端域名（不经 Nginx），需确保 CORS 配置覆盖前端来源；经 Nginx 反代同源则无跨域问题。

## 9. 监控与日常运维

### 9.1 关键日志（排障锚点）

| 子系统 | 类 | 关注点 |
|---|---|---|
| IM | `ImService` / `WsSessionManager` | 发送/投递计数、失效会话 `Iterator.remove` 清理、重连 |
| 支付 | `PayService` | 回调受理、幂等命中、金额校验拒绝、v3 验签 |
| 优惠券 | `CouponService` | `claim` 原子库存扣减、`redeem` 核销、`releaseByOrder` 释放 |
| 风控 | `RiskService` / 设备指纹 | 高风险事件、设备聚集 |

### 9.2 资金对账

- `TradeScheduler.reconcileDaily`：每日凌晨 cron 跑资金对账（结算单 vs 流水），生产务必配置时区与定时任务可用。
- 每日核对：`t_settlement` 与 `t_fund_flow`/`t_withdrawal` 一致；异常告警。

### 9.3 限流与缓存

- 限流：`IDLEFISH_RATELIMIT_ENABLED=true` 后，`RateLimitInterceptor` 按 `clientIp:path` 固定窗口（默认 200/min），按业务调整。
- 缓存：prod 用 Redis；观察缓存命中与 Redis 内存；缓存层异常 best-effort 不阻断业务。

## 10. 备份与回滚

### 10.1 数据库备份

```bash
# 每日全量 + binlog 增量（建议 cron）
mysqldump -uroot -p --single-transaction --routines --triggers idlefish > idlefish_$(date +%F).sql
```

### 10.2 应用回滚

- 版本化 jar：保留历史 `idlefish-backend-1.0.0.jar` 与对应 `V1.0.3` 分支产物；异常时切回上一版本 jar 重启。
- 数据库回滚：重大变更前先 `mysqldump` 快照；结构变更经 `schema-mysql.sql` 前向兼容（不删列/不破约束）。

### 10.3 配置回滚

- 所有环境差异走环境变量 + profile，**不修改 jar 内 yml**；回滚即恢复环境变量/配置中心旧值。

## 11. 常见排障

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 启动报 `communications link failure` | MySQL 未起 / 地址错 / 库未建 | 起 MySQL，建 `idlefish` 空库（表自动初始化） |
| 启动 `SECURITY WARN: JWT default dev secret` | 未注入 `JWT_SECRET` | 生产注入 ≥32 字节密钥 |
| 支付回调 401/被拒 | 金额不符 / 重复 / 验签失败 | 核对 `amount`(分)、`payNo` 幂等、v3 签名与密文 |
| 领券报 `COUPON_SOLD_OUT(30009)` | 库存抢光/限领 | 确认 `claimed_count<total_count` 与 `per_user_limit` |
| IM 收不到消息 | `useMock=true` 跳过 WS / token 失效 / 域名未配 wss | 真机设 `useMock=false`、配 socket 合法域名、检查 `AuthHandshakeInterceptor` |
| 抵扣金额异常/资损担忧 | 单位错（元/分混淆） | 全链路「分」；`CouponService.calculateDiscount` 纯函数单测已覆盖封顶/门槛 |
| Redis 连接异常（prod） | Redis 未起 / 密码错 | 保障 Redis 高可用，或临时回 `local` 缓存 |
| PC 后台白屏/接口 401 | `USE_MOCK` 未关 / `BASE` 错 / 跨域 | 核对 `api.js` 配置；经 Nginx 同源反代 |
