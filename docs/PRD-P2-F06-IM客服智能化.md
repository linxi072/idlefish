## 一、背景与问题

二手交易的咨询密度远高于一手电商：**商品唯一**（每个二手品状态不同）、**议价普遍**、**售后高频**，导致 IM 成为人力黑洞：

- **重复咨询占比高**：「还在吗」「包邮吗」「能不能便宜点」「什么时候发货」占绝大多数，人工客服价值低但耗时长。
- **响应不及时**：卖家非全职，夜间/工作日咨询无人应答，直接流失成交（IM 是转化漏斗的关键一环）。
- **纠纷升级无预判**：F-17 工单往往是「沟通恶化后的结果」，当前缺少在 IM 阶段识别纠纷苗头并提前干预的能力。
- **客服知识分散**：退换规则、鉴定流程、物流时效散落在各处，人工回复口径不一致，易引发承诺纠纷。

**现有可复用资产**：IM 双向通知链路已真实化并有压测脚本（`im-loadtest.js --mock` 投递率 100%）；F-17 工单状态机与举证阶段可作为「升级出口」；F-14.3 屏蔽词库可复用于会话内容安全。

---

## 二、目标与非目标

**目标（可度量）**
- G1：常见咨询（发货/议价/退换/鉴定/物流）**自动应答解决率 ≥ 60%**（无需人工介入且用户未追问）。
- G2：IM **首次响应时长 P50 ≤ 30 秒**（当前依赖卖家在线，目标降至秒级）。
- G3：由 IM 会话升级为 F-17 工单的比例**下降 ≥ 20%**（纠纷预判 + 提前干预）。
- G4：自动应答的**违规/错误回复率 ≤ 1%**（含承诺性表述、金额错误、隐私泄露）。

**非目标**
- 不做完全无人客服：**纠纷、退款、人身/财产争议一律转人工**，AI 不得自行裁决。
- 不替代 F-17 工单的裁决流程，仅提供预判与证据归集。
- 不做电话客服 / 外呼能力。
- 不承诺 7×24 全量自动覆盖（低置信度场景一律转人工）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 买家 | 作为买家，我希望深夜咨询也能立刻得到准确答复，以便快速决策是否下单 |
| 卖家 | 作为卖家，我希望常见问题由助手代答，以便我把精力放在议价与成交上 |
| 平台客服 | 作为客服，我希望接手时能看到会话摘要与纠纷预判，以便快速处理 |
| 风控 | 作为风控，我希望识别会话中的引流/诈骗话术，以便提前阻断 |
| 运营 | 作为运营，我希望维护话术知识库并查看未命中问题，以便持续提升解决率 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 系统应**始终**在自动回复中明示「由智能助手回复」，不得冒充人工或卖家 |
| REQ-02 | Event-driven | 当收到买家咨询消息后，系统应在 5 秒内返回自动应答或转人工提示 |
| REQ-03 | State-driven | 在置信度低于阈值时，系统应不作答并转人工排队 |
| REQ-04 | Unwanted | 若问题涉及退款裁决、责任判定、赔付金额承诺，系统应**不得**自动作答，直接转人工 |
| REQ-05 | Ubiquitous | 自动应答涉及金额时，应以「分」为单位计算并格式化为元展示，不得出现浮点误差 |
| REQ-06 | Event-driven | 当会话出现纠纷信号（辱骂、威胁、重复退款诉求、长时间无响应）时，系统应生成预警并提示可发起 F-17 工单 |
| REQ-07 | Event-driven | 当会话升级为人工/工单时，系统应提供会话摘要（商品、诉求、已答复内容、证据链接） |
| REQ-08 | Unwanted | 若消息命中屏蔽词库（复用 F-14.3）或检出引流/诈骗模式，系统应拦截并记录风控事件 |
| REQ-09 | Event-driven | 当用户明确要求「转人工」时，系统应立即转人工且不再继续自动作答 |
| REQ-10 | Ubiquitous | 自动应答的每一条消息应保留来源标记（知识库命中 / 模型生成 / 模板），可审计追溯 |
| REQ-11 | Optional | 若运营配置了品类专属话术，系统应优先命中品类话术再回落到通用话术 |
| REQ-12 | Unwanted | 若 LLM 服务不可用或超时，系统应回落为「已收到，卖家稍后回复」模板，**不得**阻塞消息收发 |
| REQ-13 | Ubiquitous | 会话内容与自动应答应遵守最小必要原则，禁止在应答中回显对方手机号、地址等个人信息 |
| REQ-14 | Event-driven | 当自动应答被用户点踩/追问时，系统应记录未命中问题供运营补充知识库 |

## 五、流程说明

**自动应答主流程**
```
买家消息 → 内容安全校验（REQ-08：屏蔽词/引流模式）
  → 意图识别（发货/议价/退换/鉴定/物流/闲聊/纠纷）
  → [裁决类意图 → REQ-04] 直接转人工
  → 知识库检索（品类话术优先 REQ-11 → 通用话术）
  → [命中且置信度 ≥ 阈值] 模板化应答（REQ-05 金额口径）
  → [未命中或低置信度 → REQ-03] LLM 生成 → [仍低置信] 转人工
  → 发送（带「智能助手」标识 REQ-01 + 来源标记 REQ-10）
```

**纠纷预判流程**
```
会话消息流 → 信号检测（辱骂/威胁/重复退款/超 24h 无响应）
  → 风险分累计 → [达阈值] 生成预警（REQ-06）
  → 会话内提示「如无法协商一致，可发起维权工单」+ 一键跳转 F-17
  → 同步风控事件供 F-17 举证阶段调阅
```

**升级与接管流程**
```
用户要求转人工 / 裁决类问题 / 低置信度
  → 进入人工队列 → 生成会话摘要（REQ-07）
  → 人工接管后停止自动作答（REQ-09）
```

**降级流程**：LLM 不可用/超时（REQ-12）→ 模板回复 → 消息收发不受影响。

## 六、交互说明

- **会话气泡**：自动回复气泡带「智能助手」小标签 + 来源角标（知识库/AI）；提供「有用 / 没用」反馈入口（REQ-14）。
- **转人工入口**：常驻会话右上角；用户说「转人工」立即触发（REQ-09）。
- **纠纷预警卡片**：会话内轻量提示卡（不打断对话），含「发起维权工单」按钮。
- **卖家侧开关**：卖家可关闭自动代答（部分卖家担心话术不符），关闭后仅买家侧智能提示。
- **PC 后台（新增客服助手配置）**：话术知识库 CRUD（品类/意图/答案模板）、置信度阈值、未命中问题列表与 Top 榜、自动应答质量抽检、拦截记录查询。
- **客服工作台**：会话摘要面板（商品快照 + 诉求 + 已答复 + 证据），一键创建 F-17 工单并带入上下文。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 自动解决率 | 无需人工且用户未追问的会话 / 触发自动应答会话 | ≥ 60% |
| 首次响应时长 P50 | 从买家发送到首条自动应答 | ≤ 30s（自动场景 ≤ 5s） |
| 转人工率 | 转人工会话 / 总咨询会话 | ≤ 35% |
| 错误/违规回复率 | 抽检中被判定为错误或违规的自动回复占比 | ≤ 1% |
| 纠纷升级降幅 | （基线工单转化率 − 现值）/ 基线 | ≥ 20% |
| 拦截准确率 | 拦截消息中确为违规的占比 | ≥ 85% |
| 用户满意度 | 自动应答「有用」反馈占比 | ≥ 70% |
| 服务降级触发率 | LLM 超时/失败占比 | < 3% |

**埋点**：`im_auto_reply_send`、`im_auto_reply_feedback`、`im_intent_detect`、`im_escalate_human`、`im_dispute_warning`、`im_content_block`、`im_fallback_template`。

## 八、边界场景与异常状态

1. **议价场景**：AI 不得代替卖家接受/拒绝报价，只能提供估价参考（复用 ITER-F03）并提示「以卖家回复为准」。
2. **承诺风险**：物流时效、退换承诺等须引用平台统一规则原文，禁止模型自由发挥（模板化约束）。
3. **敏感信息**：用户主动发送手机号/地址/验证码 → 应答中不得回显；验证码类直接拦截告警（REQ-13）。
4. **恶意诱导**：站外引流（加微信/QQ）、虚假发货截图 → 拦截 + 风控事件 + 会话标记。
5. **多轮上下文丢失**：长会话超窗口 → 摘要压缩，摘要错误会导致答非所问，需摘要可回溯。
6. **模型幻觉**：无知识库支撑的事实性回答（如「本平台支持七天无理由」）→ 必须绑定知识库条目，未绑定不得输出。
7. **服务降级**：LLM 不可用 → 模板兜底，不阻塞（REQ-12）。
8. **刷量攻击**：机器人刷消息 → 会话级频率限制，超限转人工告警。

## 九、权限与合规

- 自动回复**身份明示**为红线（REQ-01），不得冒充人工，避免误导用户形成承诺。
- 会话内容属个人信息，LLM 调用需评估第三方数据处理合规性（优先私有化/合规网关），并做脱敏（手机号、地址、身份证号掩码）。
- 会话数据存储与调阅需留痕（谁/何时/原因），F-17 举证调阅须绑定工单号。
- 内容安全拦截误伤需提供申诉通道；拦截记录保留可审计。
- 不得基于会话内容做与客服无关的用户画像或营销推送（目的限定）。

## 十、验收标准（可勾选）

- [ ] 自动回复均带「智能助手」标识（REQ-01）。
- [ ] 咨询 5 秒内返回应答或转人工提示（REQ-02）。
- [ ] 低置信度不作答并转人工（REQ-03）。
- [ ] 退款/责任/赔付类问题不自动作答，直接转人工（REQ-04）。
- [ ] 金额以「分」计算并正确展示（REQ-05）。
- [ ] 纠纷信号触发预警并提示可发起工单（REQ-06）。
- [ ] 升级时提供会话摘要（REQ-07）。
- [ ] 屏蔽词/引流模式命中即拦截并记录（REQ-08）。
- [ ] 用户要求转人工后停止自动作答（REQ-09）。
- [ ] 每条自动回复有来源标记可审计（REQ-10）。
- [ ] 品类话术优先于通用话术（REQ-11）。
- [ ] LLM 不可用时回落模板且不阻塞消息（REQ-12）。
- [ ] 应答中不回显对方手机号/地址等个人信息（REQ-13）。
- [ ] 点踩/追问记录入未命中问题池（REQ-14）。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | IM 消息链路与压测脚本（已具备） | 复用 `im-loadtest.js` 做自动应答后的投递率回归 |
| 依赖 | F-17 工单状态机作为升级出口 | 工单创建接口支持带入会话上下文（需扩展入参） |
| 依赖 | ITER-F03 估价（议价场景参考） | 无估价时议价仅提示「以卖家回复为准」 |
| 依赖 | LLM 服务与合规评估 | 先做知识库模板应答（零模型可用），LLM 作为增强项灰度 |
| 风险 | 模型幻觉产生承诺性表述，引发平台责任 | 事实性回答强制绑定知识库条目，未绑定不输出 |
| 风险 | 隐私数据外泄至第三方模型 | 入参脱敏 + 合规网关；红线场景禁用模型 |
| 风险 | 自动应答错误率高反而增加人工成本 | 先上线模板化高频问题，覆盖率达标后再开生成式 |
| 风险 | 离线沙箱无法调用 LLM | 意图路由与话术匹配抽为纯函数，Mockito 离线单测覆盖 |
