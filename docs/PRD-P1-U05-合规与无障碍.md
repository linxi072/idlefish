# PRD｜ITER-U05 合规与无障碍

| 项 | 内容 |
|---|---|
| 编号 | ITER-U05 |
| 维度 / 优先级 | 用户体验提升 / **P1（合规项，监管驱动）** |
| 状态 | 待评审 |
| 建议负责 | 产品负责人 + 法务合规 + 前端负责人 |
| 关联模块 | 全端（miniprogram / pc-admin / idlefish-backend）、登录与实名（WechatLoginService）、内容审核与风控关键词、F-02 通知中心与订阅消息、个人信息存储 |
| 编制日期 | 2026-10-02 |

---

## 一、背景与问题

二手交易平台涉及**大量个人信息与交易行为数据**，且用户群体跨度大（含老年用户与未成年人）。当前系统在合规与无障碍方面存在缺口：

1. **无障碍缺失**：小程序与 PC 未做适老化适配（字号、对比度、点击热区），老年用户使用困难；未做屏幕阅读器兼容。
2. **未成年人保护**：未识别未成年人身份，未限制其交易/支付行为与可用时长 —— 二手交易涉及资金与线下见面，未成年人保护属**强监管要求**。
3. **隐私授权**：个人信息收集（手机号、地址、实名）的授权告知与最小化需体系化；是否存在超范围收集、未明示用途的风险需排查。
4. **通知打扰**：订阅消息/站内信若缺乏频次控制与关闭入口，既影响体验也存在合规风险。

**行业与监管趋势**：个保法、未成年人网络保护条例、适老化无障碍改造要求持续趋严；平台未尽责可能面临整改与处罚。

---

## 二、目标与非目标

**目标（可度量）**
- G1：小程序与 PC 通过**适老化/无障碍基础要求**：正文对比度 ≥ 4.5:1、支持系统字号、关键点击热区 ≥ 44×44pt，提供「关怀模式」。
- G2：**未成年人识别与限制**上线：识别为未成年人的账号受限（交易/支付/线下见面引导），并有家长/监护人知情机制。
- G3：**隐私授权体系化**：首次收集个人信息前明示用途与范围，提供撤回授权入口；完成一次个人信息收集合规自查并留存报告。
- G4：通知打扰可控：用户可关闭营销类通知，关闭后**不再下发营销消息**（监管明确要求）。

**非目标**
- 不做完整等保/密评认证（本项聚焦产品侧合规改造）。
- 不强制实名认证所有用户（按场景最小化触发）。
- 不改变交易与资金业务规则（仅增加限制与告知）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 老年用户 | 作为老年用户，我希望开启关怀模式（更大字号与更清晰对比），以便看清并操作 |
| 未成年人 | 作为未成年用户，我希望平台限制我的交易行为，以便避免不适合的交易与风险 |
| 家长 | 作为家长，我希望知晓并管理未成年子女的账号使用，以便履行监护责任 |
| 普通用户 | 作为用户，我希望清楚知道平台收集了什么信息、可随时撤回授权，以便放心使用 |
| 法务/合规 | 作为合规方，我希望平台满足个保法与未保要求，以便通过审查 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 系统应**始终**保证正文文本对比度 ≥ 4.5:1，关键操作按钮热区 ≥ 44×44pt |
| REQ-02 | Event-driven | 当用户开启「关怀模式」时，系统应全局放大字号与间距并持久化偏好 |
| REQ-03 | Ubiquitous | 系统应**始终**支持系统字号设置（小程序跟随系统，PC 提供字号档位） |
| REQ-04 | Event-driven | 当用户被识别为未成年人时，系统应限制其交易、支付与线下见面相关功能 |
| REQ-05 | State-driven | 在未成年人模式生效期间，系统应限制可用时长与时段，并向监护人提供管理入口 |
| REQ-06 | Unwanted | 若未成年人尝试受限操作，系统应明确告知原因与申诉/监护人确认路径，**不得**静默拒绝 |
| REQ-07 | Ubiquitous | 系统应**始终**在收集个人信息前明示收集目的、方式与范围，并征得同意 |
| REQ-08 | Event-driven | 当用户撤回某项授权时，系统应停止基于该授权的处理，并停止相关功能而非静默继续使用 |
| REQ-09 | Event-driven | 当用户关闭营销类通知时，系统应立即停止下发营销消息（保留交易必需通知） |
| REQ-10 | Unwanted | 若用户关闭通知后仍收到营销消息，视为缺陷；系统应提供投诉与退订入口 |
| REQ-11 | Ubiquitous | 系统应**始终**对展示的个人信息脱敏（手机号/地址/实名），非必要不完整展示 |
| REQ-12 | Optional | 若需满足无障碍读屏，关键元素应提供可读标签（aria-label / 小程序 aria 属性） |

## 五、流程说明

**关怀模式流程**：设置开关 → 全局字号/间距/对比度切换（REQ-02）→ 偏好持久化 → 全端生效。

**未成年人限制流程**
```
识别未成年人（年龄/实名信息）
  → 进入未成年人模式（REQ-05：时长/时段限制）
  → 尝试交易/支付/线下见面 → 限制并告知原因 + 监护人确认路径（REQ-04/06）
  → 监护人可查看与管理（REQ-05）
```

**隐私授权流程**：触发收集 → 明示告知（REQ-07）→ 用户同意 → 使用；用户撤回（REQ-08）→ 停止处理 + 关闭相关功能。

**通知退订流程**：设置页关闭营销通知（REQ-09）→ 立即生效 → 交易必需通知（如支付/物流/售后）保留。

## 六、交互说明

- **关怀模式**：设置页开关；开启后字号放大、间距加大、按钮加大；PC 与小程序各自实现但视觉语言一致（对齐 ITER-U04）。
- **未成年人模式**：触发时明确弹窗说明受限范围与原因；监护人入口提供绑定与管理。
- **隐私授权弹窗**：分层展示（必要/可选），必要项说明用途，可选项允许拒绝；不得默认全选。
- **个人信息展示**：订单与商品页展示脱敏手机号/地址（REQ-11）；PC 后台导出需审批与脱敏。
- **通知设置**：区分「交易必需」与「营销推荐」两类，营销类可一键关闭（REQ-09）。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 对比度达标率 | 达标文本元素 / 总文本元素 | 100%（正文 ≥ 4.5:1） |
| 热区达标率 | ≥44pt 的关键按钮占比 | 100% |
| 关怀模式可用 | 开关可持久化且全局生效 | 是 |
| 未成年人识别准确率 | 正确识别 / 应识别 | ≥ 95%（依赖实名数据） |
| 受限操作拦截率 | 未成年人受限操作被拦截 | 100% |
| 营销退订生效 | 关闭后营销消息下发数 | **0** |
| 个人信息脱敏 | 未脱敏展示被检出数 | 0 |

**埋点**：`care_mode_enable`、`minor_mode_active`、`minor_action_blocked`、`privacy_authorize/revoke`、`notify_marketing_optout`。

## 八、边界场景与异常状态

1. **年龄数据缺失**：未实名用户无法判定年龄 → 需按场景触发实名（最小化），或对高风险行为（大额交易/线下见面）强制校验。
2. **误判成年人/未成年人**：需申诉与人工复核通道（REQ-06）。
3. **撤回授权后功能不可用**：需明确告知后果，避免用户误操作导致无法使用（REQ-08）。
4. **关怀模式与暗色模式叠加**：需保证两种模式叠加仍满足对比度（与 ITER-U03/U04 协同）。
5. **交易必需通知与营销通知混淆**：需清晰分类，避免用户关闭交易通知导致错过物流/售后。
6. **PC 后台合规**：运营查看用户信息需受 RBAC 与审计约束（ITER-T05）。

---

## 九、权限与合规

- **个保法**：收集最小化、目的明示、同意机制、可撤回、可删除；敏感信息（实名、地址）加密存储与传输。
- **未成年人保护**：识别、时长/时段限制、消费限制、监护人机制；不得诱导未成年人交易。
- **无障碍**：适老化改造属监管要求，需留存改造说明与检测记录。
- **通知合规**：营销通知必须可关闭，关闭后不得再下发；退订入口需在消息中可直接触达（REQ-10）。
- **数据留存**：个人信息留存周期需在隐私政策中明示，到期删除或匿名化。

## 十、验收标准（可勾选）

- [ ] 正文对比度 ≥ 4.5:1，关键按钮热区 ≥ 44pt（REQ-01）。
- [ ] 关怀模式可开启并持久化，全局生效（REQ-02）。
- [ ] 支持系统字号跟随 / PC 字号档位（REQ-03）。
- [ ] 未成年人交易/支付/线下见面被限制（REQ-04）。
- [ ] 未成年人模式有时长/时段限制与监护人入口（REQ-05）。
- [ ] 受限操作明确告知原因与申诉路径（REQ-06）。
- [ ] 收集个人信息前明示并征得同意（REQ-07）。
- [ ] 撤回授权后停止处理且相关功能停用（REQ-08）。
- [ ] 关闭营销通知后立即停止下发（REQ-09）。
- [ ] 提供投诉与退订入口，关闭后零营销消息（REQ-10）。
- [ ] 个人信息展示脱敏（REQ-11）。
- [ ] 完成个人信息收集合规自查并留存报告。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | 实名/年龄数据能力（WechatLoginService、实名校验） | 按场景最小化触发，高风险行为强制校验 |
| 依赖 | ITER-U04 设计令牌（关怀模式改字号/间距需令牌支撑） | 并行推进，关怀模式作为令牌用例 |
| 依赖 | ITER-T05 数据权限（后台查看用户信息的合规约束） | 复用 RBAC 与审计 |
| 风险 | 未成年人识别依赖实名数据，覆盖率不足 | 高风险行为强制校验；提供申诉复核 |
| 风险 | 适老化改动影响现有布局（放大后错位） | 令牌化字号/间距 + 关键页面走查 |
| 风险 | 隐私弹窗过于复杂影响转化 | 分层展示，必要/可选分离，允许先使用后补授权 |
| 风险 | 法规更新导致要求变化 | 规范与法务保持同步，PRD 标注需法务最终确认 |
