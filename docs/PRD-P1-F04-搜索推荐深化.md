## 一、背景与问题

F-14.1~F-14.3 已交付可用的检索与推荐能力：ES ik 分词 + 筛选聚合 + 索引重建（重建期间降级不报错）、推荐为「行为加权 + 热度衰减 + 冷启动」、搜索词运营支持热搜/历史/屏蔽词/同义词。

**现存不足**
1. **特征离线、反馈滞后**：推荐综合分依赖离线计算的行为加权，用户实时兴趣（刚浏览/刚搜索）不能立刻影响 feed。
2. **召回单一**：以关键词/规则召回为主，缺少语义（向量）召回，同义表达与图文语义匹配能力弱（如搜「苹果手机」应命中 iPhone）。
3. **无实验体系**：算法策略调整无法 AB 评估，迭代靠拍脑袋，劣化不能快速回滚。
4. **搜推割裂**：搜索词运营（热搜/同义词）与推荐各自为政，用户搜索意图未反哺推荐。
5. **冷启动粗糙**：新用户/新商品仅靠热度兜底，首屏相关性差。

---

## 二、目标与非目标

**目标（可度量）**
- G1：搜索**首位点击率（CTR@1）提升 ≥ 15%**（AB 口径）。
- G2：推荐 feed **人均点击数提升 ≥ 20%**，**成交转化贡献提升 ≥ 10%**。
- G3：支持**实时特征**：用户行为发生后 60 秒内影响推荐结果。
- G4：建立 **AB 实验框架**，任一策略可分流、可度量、可一键回滚。
- G5：语义召回覆盖后，**零结果率下降 ≥ 30%**。

**非目标**
- 不替换 ES 为全新检索引擎（在现有 ES 上增强）。
- 不做个性化定价（与估价区分）。
- 不承诺具体算法指标上限（以 AB 实测为准）。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 买家（有明确意图） | 作为买家，我希望用口语化描述也能搜到想要的商品，而不是零结果 |
| 买家（逛） | 作为买家，我希望首页 feed 反映我刚看过的兴趣，而不是只看热度 |
| 新用户 | 作为新用户，我希望冷启动也能看到相关内容，而不是千篇一律的热榜 |
| 运营 | 作为运营，我希望策略调整能 AB 验证，劣化可快速回滚 |
| 算法 | 作为算法，我希望有实时特征与实验框架，以便快速迭代模型 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Event-driven | 当用户发生浏览/搜索/收藏/加购行为时，系统应在 60 秒内更新该用户的实时兴趣特征 |
| REQ-02 | Event-driven | 当用户提交搜索词时，系统应结合语义召回与关键词召回返回融合排序结果 |
| REQ-03 | Unwanted | 若语义召回服务不可用，系统应降级为纯关键词召回，**不得**返回空结果或报错 |
| REQ-04 | Event-driven | 当搜索返回零结果时，系统应基于同义词（F-14.3）与语义相似给出「猜你想找」的替代结果 |
| REQ-05 | State-driven | 在用户处于冷启动状态（行为数低于阈值）期间，系统应使用类目偏好 + 同城 + 热度兜底策略 |
| REQ-06 | Event-driven | 当运营配置 AB 实验时，系统应按分流规则将用户稳定分桶，并保证同一用户分桶一致 |
| REQ-07 | Unwanted | 若实验组指标显著劣化，系统应支持一键切回对照组（回滚） |
| REQ-08 | Ubiquitous | 系统应**始终**应用 F-14.3 配置的屏蔽词与同义词，大小写不敏感 |
| REQ-09 | Event-driven | 当用户搜索意图明确时，系统应将该意图作为特征反哺推荐 feed |
| REQ-10 | Unwanted | 若 ES 索引重建中，系统应降级到可用副本或旧索引，**不得**中断搜索服务 |

## 五、流程说明

**搜索流程（增强后）**
```
查询词 → 屏蔽词校验（REQ-08）→ 同义词归一化
  → 并行召回：关键词召回（ES ik）+ 语义召回（向量）
  → 融合排序（实时特征 + 行为加权 + 热度衰减）
  → 零结果？→ [REQ-04] 语义相似 + 同义词扩展给出替代
  → 返回结果（埋点：曝光/点击/零结果率）
```

**推荐流程（增强后）**
```
用户请求 feed → 取实时兴趣特征（REQ-01）+ 长期画像
  → 召回（协同/语义/类目/同城）→ 综合排序
  → 冷启动？→ [REQ-05] 兜底策略
  → AB 分桶（REQ-06）→ 返回（埋点曝光/点击/成交归因）
```

**实验流程**：配置实验（分桶比例/策略参数）→ 分流 → 埋点采集 → 指标对比 → 显著劣化则回滚（REQ-07）。

## 六、交互说明

- **搜索页**：结果列表保持现有样式；零结果页改为「猜你想找」卡片（REQ-04），并展示热搜词引导。
- **首页 feed**：保持瀑布流；新增推荐理由标签（如「与你刚浏览的相似」「同城」），提升可解释性。
- **PC 后台（搜索词运营页扩展）**：新增「实验管理」Tab（实验列表/分桶比例/指标对比/启停回滚）、「语义召回开关」、「零结果分析」报表。
- **BI（F-14.5）**：新增 CTR@1、零结果率、feed 点击/转化归因看板。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| CTR@1 | 首位结果点击 / 搜索次数 | 提升 ≥ 15% |
| 零结果率 | 零结果搜索 / 总搜索 | 下降 ≥ 30% |
| feed 人均点击 | 点击数 / 活跃用户 | 提升 ≥ 20% |
| 推荐成交贡献 | 推荐链路成交 GMV / 总 GMV | 提升 ≥ 10% |
| 实时特征时延 | 行为发生 → 特征生效 | ≤ 60s |
| 实验可回滚 | 劣化实验回滚耗时 | ≤ 5 分钟 |
| 语义召回可用性 | 降级触发次数 / 请求数 | < 1% |

**埋点**：`search_query`、`search_result_expose/click`、`search_zero_result`、`feed_expose/click`、`rec_reason_show`、`ab_bucket_assign`、`deal_attribution`。

## 八、边界场景与异常状态

1. 语义召回服务超时/不可用 → 降级纯关键词（REQ-03）。
2. ES 索引重建期间查询 → 降级旧索引，不中断（REQ-10）。
3. 新用户无任何行为 → 冷启动兜底，且需主动引导选偏好类目。
4. 新商品无曝光无行为 → 需新品扶持流量（保量曝光），否则永远冷启动。
5. 实验分桶穿越（同一用户跨设备/重登）→ 分桶需按用户 ID 稳定，不按设备。
6. 屏蔽词配置变更 → 需即时生效且不影响已有索引（查询期过滤）。
7. 搜索攻击（高频异常词刷屏）→ 需限流与异常词监控。

---

## 九、权限与合规

- 屏蔽词/同义词配置属运营权限，需 RBAC + 留痕；屏蔽词不得被用于规避监管要求内容。
- 用户行为数据采集需符合个保法，提供关闭个性化推荐的开关（合规要求）。
- 推荐理由标签不得泄露敏感推断（如基于健康、宗教等敏感属性）。
- AB 实验涉及用户分流，需保证同一用户分桶稳定，不频繁切换造成体验抖动。

## 十、验收标准（可勾选）

- [ ] 用户行为 60 秒内影响推荐结果（REQ-01）。
- [ ] 搜索融合语义与关键词召回（REQ-02）。
- [ ] 语义召回不可用时降级且不空结果/不报错（REQ-03）。
- [ ] 零结果页展示「猜你想找」替代结果（REQ-04）。
- [ ] 冷启动用户走兜底策略且首屏相关（REQ-05）。
- [ ] AB 实验可稳定分桶（REQ-06）。
- [ ] 劣化实验可一键回滚，≤5 分钟（REQ-07）。
- [ ] 屏蔽词与同义词始终生效且大小写不敏感（REQ-08）。
- [ ] 搜索意图反哺推荐 feed（REQ-09）。
- [ ] 索引重建期间搜索不中断（REQ-10）。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | ES（已真实接入）、向量召回组件（需新增，可能引入新依赖） | 评估离线构建可行性；不可行则先用 ES 现有能力近似 |
| 依赖 | 实时特征存储（Redis 已有，可复用） | 复用 Redis 单一缓存实现，避免新组件 |
| 风险 | 引入向量召回/新依赖破坏 `mvn -o` 离线构建 | 先验证依赖入 `.m2`；否则降级为 ES 内置近似方案 |
| 风险 | AB 实验框架自研成本高 | 先做最简分桶 + 埋点对比，不做复杂统计显著性引擎 |
| 风险 | 推荐理由标签引发用户不适（过度精准） | 提供关闭个性化开关，理由标签克制表达 |
| 风险 | 指标提升不达预期 | 以 AB 实测为准，设定止损线，不达标则回滚并复盘 |
