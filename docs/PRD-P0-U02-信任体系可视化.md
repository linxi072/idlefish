# PRD｜ITER-U02 信任体系可视化

| 项 | 内容 |
|---|---|
| 编号 | ITER-U02 |
| 维度 / 优先级 | 用户体验提升 / **P0** |
| 状态 | 待评审 |
| 建议负责 | 产品负责人（信任规则）+ 设计负责人（标识体系）+ 前端（小程序/PC） |
| 关联模块 | ITER-F02 鉴定验货、F-06 评价与信用、F-17 售后维权工单、F-02 通知中心、资金托管（`RealWechatEscrowServiceImpl` 担保交易）、`logisticsTrack` 物流轨迹 |
| 编制日期 | 2026-10-02 |

---

## 一、背景与问题

二手交易的转化瓶颈在**信任**，但当前信任信息是**分散且不可见的**：

- 卖家的信用（F-06 评价与信用）未在商品决策路径（详情页/下单页）前置展示，买家需自行翻找。
- 资金安全（担保交易：买家付款先进平台托管，确认收货后放款）**从未向用户明示**，买家担心付款后钱货两空。
- 售后保障（F-17 工单：争议状态机 + 双方举证 + 平台裁决）仅在出事后可见，**事前无感知**，买家不敢下单。
- 验货标识（ITER-F02）尚未落地，商品缺少中立质检背书。

**结果**：高客单价商品浏览多、下单少；新卖家无信用积累时几乎无法成交。

**行业趋势**：头部平台将「信任可视化」作为转化基建——验货标、信用等级、交易保障条款、售后进度条一并前置到决策路径。

---

## 二、目标与非目标

**目标（可度量）**
- G1：高客单价商品（≥ 1000 元）**下单转化率提升 ≥ 15%**（AB 实验口径）。
- G2：商品详情页信任模块**曝光可见率 100%**（首屏或近首屏可见，不折叠）。
- G3：因「担心不发货/货不对板」类原因发起的**咨询与争议下降 ≥ 20%**。
- G4：售后进度可追踪后，工单「催单」类消息量下降 ≥ 25%。

**非目标**
- 不改变信用分计算规则（F-06 已有逻辑，本项仅做展示与口径呈现）。
- 不改变资金托管与售后流程本身（仅做可视化与说明）。
- 不承诺「100% 无风险」，所有保障需明示适用条件与边界。

## 三、目标用户与用户故事

| 角色 | 用户故事 |
|---|---|
| 买家（首单） | 作为首次购买的用户，我希望下单前看到资金托管与售后保障说明，以便放心付款 |
| 买家（高客单） | 作为买数码/奢侈品的用户，我希望看到验货标与卖家信用，以便判断可信度 |
| 卖家（新号） | 作为新卖家，我希望有清晰的成长路径（如何提升信用），以便获得曝光与成交 |
| 买卖双方 | 作为交易任一方，我希望售后进度可实时查看，以便减少反复催问 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Ubiquitous | 系统应**始终**在商品详情页首屏区域展示卖家信用摘要（信用等级/评分/成交数） |
| REQ-02 | Event-driven | 当商品已完成验货并通过时，系统应在商品卡片与详情页展示「已验」标识及报告入口 |
| REQ-03 | Ubiquitous | 系统应**始终**在下单确认页展示资金保障说明（付款托管、确认收货后放款） |
| REQ-04 | Event-driven | 当买家点击保障说明时，系统应展开完整条款（适用范围、时效、不适用情形） |
| REQ-05 | State-driven | 在售后工单处于任一处理状态时，系统应在订单与工单页展示**进度条与当前节点**（举证/裁决/完成） |
| REQ-06 | Event-driven | 当工单状态变更时，系统应通过站内信（F-02）与订阅消息双向通知买卖双方 |
| REQ-07 | Event-driven | 当物流状态更新时（复用 `logisticsTrack`），系统应在订单详情同步展示时间轴 |
| REQ-08 | Unwanted | 若卖家信用数据不可用或新卖家无数据，系统应展示「新卖家 · 暂无信用」而非空白或误导性高分 |
| REQ-09 | Event-driven | 当卖家账号处于封禁/风控处置状态时，系统应在其商品页展示风险提示，并限制下单 |
| REQ-10 | Optional | 若商品属于高客单但未验货，系统应展示「建议验货」提示与验货入口 |
| REQ-11 | Ubiquitous | 系统应**始终**明示保障的适用边界（如虚拟商品、违禁品不适用），不得过度承诺 |

## 五、流程说明

**买家决策路径（信任信息植入点）**
```
列表页/推荐 → 商品卡片（已验标、信用标）
  → 商品详情页首屏：信用摘要 + [可选]验货标 + 报告入口 + 保障提示
  → 下单确认页：资金保障说明（可展开条款） + 验货入口（高客单）
  → 支付（资金进托管）
  → 订单详情：物流时间轴 + 售后入口 + 工单进度（如有）
  → 确认收货 → 放款卖家
```

**售后可视化路径**
```
发起工单 → 双方举证 → 平台裁决 → 结果执行
  全程：订单页/工单页展示进度条（当前节点高亮）+ 状态变更双向通知
```

## 六、交互说明

- **信任标识体系（需设计统一规范）**：`已验`（金色盾牌）、`信用等级`（L1~L5 徽章，复用会员等级视觉）、`交易保障`（蓝盾）、`风险提示`（红标）。标识需与 PC 后台、小程序一致（后续并入 ITER-U04 设计系统）。
- **商品详情页**：首屏下方「信任条」横排展示 —— 已验标 / 信用等级 / 交易保障；点击任一项弹出说明层。
- **下单确认页**：资金保障一句话说明 + 「了解详情」展开；高客单商品展示「建议验货」卡片（REQ-10）。
- **订单详情**：物流时间轴（复用现有 timeline 样式）+ 售后进度条（节点：已申请→举证中→裁决中→已完成）。
- **新卖家**：展示「新卖家 · 暂无信用」并给成长引导（完成实名/首单/好评可提升）。
- **PC 后台**：订单/工单管理页同步展示验货与信用字段，便于客服判断。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 高客单转化率 | ≥1000 元商品下单 / 浏览 | 提升 ≥ 15%（AB） |
| 信任模块曝光率 | 首屏可见的商品页 / 总商品页 | 100% |
| 信任标识点击率 | 点击说明 / 曝光 | 观察指标（不做硬目标） |
| 信任类争议下降 | 「不发货/货不对板」工单占比降幅 | ≥ 20% |
| 工单催单量降幅 | 催单消息量降幅 | ≥ 25% |
| 验货标覆盖率 | 展示已验标的商品 / 已验商品 | 100% |

**埋点**：`trust_module_view`、`trust_badge_click`、`guarantee_detail_expand`、`aftersale_progress_view`、`verify_badge_view/click`。

## 八、边界场景与异常状态

1. 新卖家/零成交卖家无信用数据 → 展示「暂无信用」，不得显示 misleading 高分（REQ-08）。
2. 卖家被封禁但商品仍在架 → 展示风险提示并限制下单（REQ-09）。
3. 验货中（未出结果）商品 → 展示「验货中」，不得展示「已验」。
4. 工单被撤回/关闭 → 进度条需正确终态展示，不留「进行中」残留。
5. 虚拟商品/违禁品类不适用保障 → 明示不适用（REQ-11）。
6. 信用数据延迟（缓存/异步）→ 允许短暂旧值，但不得为空。

---

## 九、权限与合规

- 信用分/评价属用户数据，展示需符合个保法；不得展示卖家实名、手机号等敏感信息。
- 交易保障条款需法务评审，明确适用范围与免责边界，**不得**做「100% 无风险」等过度承诺。
- 验货标识仅在真实验货通过后展示，伪造/误展示属合规风险（需与 ITER-F02 报告强绑定）。
- 封禁/风控标识涉及用户名誉，仅展示客观风险提示，不展示具体风控规则细节。

## 十、验收标准（可勾选）

- [ ] 商品详情页首屏可见卖家信用摘要（REQ-01）。
- [ ] 已验商品在卡片与详情页展示「已验」标及报告入口（REQ-02）。
- [ ] 下单确认页展示资金保障说明且可展开完整条款（REQ-03/04）。
- [ ] 售后工单任一状态均有进度条与当前节点（REQ-05）。
- [ ] 工单状态变更触发双向通知（REQ-06）。
- [ ] 物流更新同步到订单详情时间轴（REQ-07）。
- [ ] 新卖家无信用时展示「暂无信用」而非空白或高分（REQ-08）。
- [ ] 封禁卖家商品页展示风险提示并限制下单（REQ-09）。
- [ ] 高客单未验货商品展示「建议验货」入口（REQ-10）。
- [ ] 保障条款明示适用边界，无过度承诺（REQ-11）。
- [ ] PC 后台同步展示验货与信用字段。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | ITER-F02 验货体系（提供「已验」标识与报告） | 并行开发；无验货时先上信用 + 保障 + 售后进度 |
| 依赖 | F-06 评价与信用（数据来源）、F-17 工单状态机（进度节点） | 已具备，直接读取 |
| 依赖 | F-02 通知中心 / 订阅消息（双向通知） | 已具备 |
| 风险 | 信任标识过多造成视觉噪音 | 首屏最多 3 个标识，其余折叠进「更多保障」 |
| 风险 | 保障条款与法务口径不一致引发纠纷 | 上线前法务评审，条款版本化管理 |
| 风险 | 验货标误展示（机构结果未回传即展示） | 标识与报告快照强绑定，无报告不展示 |
