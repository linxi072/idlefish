## 二、本次补全 / 修复的具体功能（含验证证据）

### 1. 修复编译与装配缺陷（前置阻塞）
- **`@MapperScan` 收窄**（`TradeApplication`）：原 `@MapperScan("com.idlefish.trade")` 过宽，把 `SearchService` 等**服务接口**误当作 MyBatis Mapper 代理，导致 `query/suggest` 抛 `Invalid bound statement`。改为仅扫描 `*.mapper` 七个包。→ 已验证：`/api/search/query`、`/suggest`、`/fallback` 均返回 `code=0`。
- **补齐缺失 import / 字段注入**：`ItemService`（ItemStatusLogMapper）、`OrderService`（TrackService）、`TradeScheduler`（ReconciliationService）、`SearchController`（RecommendService）。→ 后端 `mvn -o test-compile` 通过（EXIT=0）。

### 2. 议价 D3（原「未开始」→ 已完成）
- 新增 `Bargain` / `BargainMapper` / `BargainCreateDTO` / `BargainService` / `BargainController`；`t_bargain` 建表 + 索引（`schema-mysql.sql`）；data-mysql.sql 无关。
- 逻辑：发起（24h 过期）、接受（同步成交价到商品）、会话内列表、定时过期。
- **验证**：卖家发布商品 → 买家发起议价（status=pending）→ 卖家接受（status=accepted），端到端通过。

### 3. 推荐流 C2（原「未开始」→ 已完成）
- 新增 `RecommendService.feed(city,page,size)`：同城优先 + 热度分（view + fav*5 + like*3）。
- `SearchController` 暴露 `GET /api/search/recommend`；小程序 `api.recommend` + `index.js` 切换推荐/搜索。
- **验证**：`/api/search/recommend?city=Shanghai` 返回 `code=0`。

### 4. 客服入口 D4（原「进行中」→ 已完成）
- `ImService.csConversation` 已实现但**缺少 controller 映射**（上一轮漏接）。本回合在 `ImController` 补 `POST /api/im/cs-entry`，返回 `{convId, peerId=10000, itemId}`。
- **验证**：带/不带 itemId 均返回 `code=0` 与 convId。

### 5. IM 消息序号 E1 + 敏感词折叠 E4（上一轮代码未落地，本回合补齐）
- `ImService.send` 补：`msg.setContent(SensitiveWords.fold(content))` 与 `msg.setSeq(messageMapper.maxSeqByConv(convId)+1)`；`Message`/`MessageVO` 增加 `seq` 字段；`MessageMapper.maxSeqByConv`；`t_message` 增加 `seq` 列。
- **验证**：发送含「加我微信」的消息 → 返回 `content="***"`、`seq=1`。

### 6. 下单埋点 D1
- `OrderService.createOrder` 在写入 PayOrder 后调用 `trackService.track(buyerId,"order_create",orderNo,null)`（try/catch 包裹，失败不影响主流程）。

### 7. 商品状态流转留痕 B4
- `ItemService.setStatus` 改为先取旧状态、改状态后写 `t_item_status_log`（from/to/operator/remark）；`ItemStatusLog` 实体 + Mapper + 建表已就绪，`toVO` 放宽为 `public` 供推荐复用。

### 8. 结算风控冻结 D7（确认已落地）
- `SettlementService.processDue` 对到期结算单：卖家存在 open 风控事件 → `frozen`；否则 CAS 认领放款；新增 `unfreeze(id)`（frozen→pending）。

### 9. 对账与提现 F4（确认已落地 + 补每日任务）
- `ReconciliationService.reconcile(day)`：比对已支付订单金额 vs PAY 资金流水，返回 expected/actual/diff/matched。
- `WithdrawalService`：余额计算、申请即冻结（FREEZE）、审批出账（WITHDRAW）、驳回、账号脱敏。
- `AdminController` 暴露 attr-templates / withdrawals / reconciliation / settlements/{id}/unfreeze 等。
- **本回合补充**：`TradeScheduler.reconcileDaily`（`@Scheduled(cron="0 0 2 * * *")`）调用对账并告警。
- **验证**：`/api/admin/reconciliation?day=2026-09-23` 返回 `code=0, matched=true`；`/api/admin/attr-templates?categoryId=1011` 返回种子 3 条，新增后变 4 条；提现列表返回 `code=0`。

### 10. 前端小程序（`miniprogram`，语法校验通过 `node --check`）
- `utils/api.js` 新增 `recommend/csEntry/createBargain/acceptBargain`；`pages/chat/chat.js` 发起议价 + 接受；`chat.wxml` 议价卡片「接受」按钮；`pages/index/index.js` 同城推荐流。
