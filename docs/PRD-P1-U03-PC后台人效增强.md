# PRD｜ITER-U03 PC 运营后台人效增强

| 项 | 内容 |
|---|---|
| 编号 | ITER-U03 |
| 维度 / 优先级 | 用户体验提升 / **P1** |
| 状态 | 待评审 |
| 建议负责 | 前端负责人 + 产品负责人（运营流程） |
| 关联模块 | pc-admin（Vite + Vue3 SFC + Element Plus）、`global.css` 设计令牌、菜单重组（10 个一级目录）、`listPageMixin` / `crudDialogMixin`、`TreeFlatTable`、F-14.5 / F-15.5 运营 BI |
| 编制日期 | 2026-10-02 |

---

## 一、背景与问题

pc-admin 已完成 Vite SFC 迁移与 UI 优化（设计令牌、响应式、菜单按业务模块重组、树状页扁平化），基础体验已显著改善。但**运营日常高频操作仍存在效率瓶颈**：

1. **无批量操作**：商品审核、上下架、风控处置等只能逐条点，日常处理上百条时人效极低。
2. **筛选条件无法复用**：运营每天重复设置相同筛选（如「待审核 + 数码类目 + 近 7 天」），每次重新点选。
3. **数据无法下钻**：BI 看板与列表页脱节，看到异常不能一键追到明细单。
4. **无暗色模式**：值班/夜间使用刺眼；设计令牌已就绪（`:root` 变量），具备落地条件。
5. **关键操作缺二次确认的部分场景**：部分高危操作（批量删除、批量封禁）风险高但无统一确认与撤销机制。

---

## 二、目标与非目标

**目标（可度量）**
- G1：批量操作覆盖后，商品审核/上下架**单条平均处理耗时下降 ≥ 50%**。
- G2：筛选模板可保存/复用，**常用筛选设置次数下降 ≥ 70%**。
- G3：BI 异常指标可**一键下钻**至明细列表，下钻成功率 100%。
- G4：暗色模式可用，且**对比度满足 WCAG AA**（正文 ≥ 4.5:1）。
- G5：批量高危操作**误操作事故 = 0**（二次确认 + 可撤销）。

**非目标**
- 不重构现有 mixin 与页面结构（在其上增强）。
- 不做移动端运营（PC 定位不变）。
- 不新增业务模块（本项只提升操作效率）。

| 角色 | 用户故事 |
|---|---|
| 审核运营 | 作为审核运营，我希望批量通过/驳回待审商品，以便处理每日上百条 |

## 四、需求清单（EARS）

| 编号 | 类型 | 需求描述 |
|---|---|---|
| REQ-01 | Event-driven | 当用户在列表页勾选多条记录时，系统应展示批量操作栏（审核/上下架/导出） |
| REQ-02 | Unwanted | 若批量操作包含不允许处理的记录（如已完结/无权限），系统应跳过并明确告知跳过原因与条数 |
| REQ-03 | Unwanted | 若批量操作为高风险（删除/封禁/改价），系统应**强制二次确认**并展示影响条数与范围摘要 |
| REQ-04 | Event-driven | 当批量操作执行时，系统应展示进度（成功/失败/跳过），并提供失败明细导出 |
| REQ-05 | Unwanted | 若批量操作部分失败，系统应保证已成功项生效且不回滚（幂等），并支持对失败项重试 |
| REQ-06 | Event-driven | 当用户保存筛选条件为模板时，系统应支持命名、设为默认、删除与共享给同角色 |
| REQ-07 | Event-driven | 当用户在 BI 看板点击某指标/图表区块时，系统应携带该维度条件跳转至对应明细列表 |
| REQ-08 | Event-driven | 当用户切换暗色模式时，系统应全局切换且记住偏好（本地存储） |
| REQ-09 | Ubiquitous | 暗色模式应**始终**基于设计令牌实现，禁止硬编码颜色绕过令牌 |
| REQ-10 | Unwanted | 若某组件在暗色下对比度不足，系统应通过令牌覆盖修正，不得出现不可读文本 |
| REQ-11 | Event-driven | 当批量操作完成后，系统应记录操作日志（操作人/条数/条件/结果）供审计 |
| REQ-12 | Optional | 若用户误操作，系统应在限定时间窗内提供「撤销」入口（仅限可逆操作） |

## 五、流程说明

**批量操作流程**
```
列表页勾选 → 批量操作栏出现（REQ-01）
  → 选择操作 → [高风险] 二次确认 + 影响摘要（REQ-03）
  → 执行（进度条，REQ-04）
  → 结果：成功/失败/跳过 → 失败明细可导出（REQ-02/05）
  → 记录操作日志（REQ-11）→ [可逆操作] 提供限时撤销（REQ-12）
```

**筛选模板流程**：设置条件 → 保存为模板（命名/默认/共享，REQ-06）→ 下次一键应用。

**下钻流程**：BI 看板 → 点击指标 → 携带维度跳转明细列表（REQ-07）→ 可继续筛选/批量处理。

---

## 六、交互说明

- **列表页**：表头增加多选列；勾选后出现底部固定批量操作栏（不遮挡分页）；操作栏显示「已选 N 条」。
- **二次确认弹窗**：明确展示「将影响 N 条记录」+ 范围摘要 + 不可撤销提示（REQ-03）。
- **进度与结果**：批量执行中显示进度条；结束弹窗列出成功/失败/跳过数量，失败项可导出 CSV。
- **筛选模板**：筛选栏右侧「保存为模板」；模板下拉可快速应用/管理。
- **BI 下钻**：图表区块可点击，hover 提示「点击查看明细」；跳转后筛选条件回填并可二次编辑。
- **暗色模式**：顶栏提供切换开关（太阳/月亮图标），偏好持久化（REQ-08）。

## 七、数据口径与指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 单条处理耗时 | 批量后单条平均耗时降幅 | ≥ 50% |
| 筛选模板使用率 | 使用模板的查询 / 总查询 | ≥ 60% |
| 下钻成功率 | 成功跳转并回填条件 / 下钻点击 | 100% |
| 暗色对比度 | 正文文本对比度 | ≥ 4.5:1（WCAG AA） |
| 批量误操作事故 | 批量操作导致的误处理事件 | 0 |
| 批量失败可追溯 | 失败明细可导出比例 | 100% |

**埋点（PC 侧）**：`batch_select`、`batch_execute`、`batch_result`、`filter_template_save/apply`、`bi_drilldown`、`theme_toggle`。

## 八、边界场景与异常状态

1. **跨页全选**：勾选「全选」应明确是「当前页」还是「全部筛选结果」，避免误操作海量数据。
2. **批量上限**：单次批量需设上限（如 200 条），超限提示分批，避免超时与资源打满。
3. **并发冲突**：运营 A、B 同时处理同一批 → 需幂等与乐观锁，重复处理给出提示而非静默覆盖。
4. **网络中断**：批量执行中断网 → 已成功项保留，恢复后可查看结果而非重复提交。
5. **暗色模式下的图表**：ECharts 需同步切换主题（`window.echarts` 已可用），否则图表仍为亮色。
6. **筛选模板共享**：共享给同角色后，他人修改/删除需权限控制。

---

## 九、权限与合规

- 批量操作需受 RBAC 控制，无权限的批量动作不展示。
- 批量删除/封禁/改价等**高危操作**强制二次确认 + 操作日志（REQ-11），满足审计要求。
- 操作日志需包含操作人、时间、条件、影响条数、结果，可导出用于合规审计。
- 筛选模板共享不得泄露他人私有条件（共享需显式授权）。

---

## 十、验收标准（可勾选）

- [ ] 列表页可多选并出现批量操作栏（REQ-01）。
- [ ] 不合法记录被跳过并说明原因与条数（REQ-02）。
- [ ] 高风险批量操作强制二次确认并展示影响摘要（REQ-03）。
- [ ] 执行中有进度，结果可区分成功/失败/跳过（REQ-04）。
- [ ] 部分失败不回滚已成功项，失败项可重试（REQ-05）。
- [ ] 筛选条件可保存为模板并复用/共享（REQ-06）。
- [ ] BI 指标可一键下钻至明细并回填条件（REQ-07）。
- [ ] 暗色模式可切换且记住偏好（REQ-08）。
- [ ] 暗色基于令牌实现，无硬编码颜色（REQ-09）。
- [ ] 暗色下无对比度不足文本（REQ-10）。
- [ ] 批量操作有完整操作日志（REQ-11）。

## 十一、依赖与风险

| 类型 | 说明 | 应对 |
|---|---|---|
| 依赖 | 设计令牌（`global.css :root`）已就绪 | 暗色通过令牌覆盖实现，成本低 |
| 依赖 | F-14.5 / F-15.5 BI 接口（下钻需维度参数） | 与后端确认下钻参数契约，纳入 ITER-T03 |
| 风险 | 批量操作引发大规模误处理 | 上限控制 + 二次确认 + 日志 + 可逆操作撤销 |
| 风险 | 暗色模式下第三方组件（Element Plus/ECharts）主题不全 | 优先覆盖高频页面，遗漏项迭代补齐 |
| 风险 | 批量接口性能（大批量超时） | 分批异步处理 + 进度反馈 + 失败明细导出 |
| 风险 | 破坏离线构建/现有 mixin | 增强而非重构，改动后全量页面走查 |
