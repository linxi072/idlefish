# F-10 真机联调验证手册（IM 实时 / 支付回流 / 优惠券营销）

> 适用范围：闲置集二手交易小程序 **V1.0.3** 分支。
> 目标：在真机/本地后端环境，验证 **IM 实时消息收发稳定性与延迟**、**支付完成后回流链路（支付回调、订单状态同步）**、以及 **优惠券领取/发放/核销等营销场景** 的端到端功能正常、数据一致、无异常遗漏。
> 配套脚本：`scripts/im-loadtest.js`、`scripts/pay-callback-sim.js`（均支持 `--mock` 离线验证与 `--live` 真机联调）。

---

## 0. 联调总览与验收口径

| 验证域 | 关键链路 | 验收口径（无异常遗漏） |
|---|---|---|
| IM 实时 | WS 连接 → 收发 → serverTime 打点 → 重连 | 送达率 ≥ 99%；P95 延迟可控；断线后指数退避重连成功；失效会话被清理 |
| 支付回流 | 支付回调 → 订单状态同步 → 资金流水 → 双向通知 | 回调后订单 `status=paid`；资金流水仅 1 条（幂等）；金额不符回调被拒 |
| 优惠券 | 领券中心领取 → 我的券 → 结算核销 → 订单详情抵扣 → 取消释放 | 库存原子扣减；门槛/范围/时效校验；抵扣金额正确；取消订单券回退 UNUSED |

## 2. IM 实时消息联调

### 2.1 联调脚本
```bash
# 本地模拟：验证前端延迟测量口径（无需后端，约数秒）
node scripts/im-loadtest.js --mock --rounds 100 --min-ms 15 --max-ms 60

# 真机/本地后端：两个用户登录取 JWT 各开一条 WS，互发并测延迟（需 npm i ws）
node scripts/im-loadtest.js --live http://localhost:8080 --users 2 --rounds 200
```
- WS 端点（对齐 `AuthHandshakeInterceptor`）：`ws(s)://<apiBaseUrl>/ws/im?token=<JWT>`。
- 前端延迟口径：`MessageVO.serverTime` 由后端 `ImService.push` 打点（`System.currentTimeMillis()`），`chat.js` 以 **接收时刻 − serverTime** 测算端到端延迟；`WsSessionManager.send` 返回实际投递数并清理失效会话。

### 2.2 验收项
1. 双端互发文本/议价卡片，消息在对方会话列表即时出现（延迟取 `serverTime` 口径）。
2. 杀掉一端网络/进程，另一端 `onError` 触发 **25s 心跳保活 + 指数退避重连（3s→30s）**，恢复后消息不丢（`seq` 去重）。
3. 高频压测（rounds=200+）下送达率 ≥ 99%，P95 延迟稳定；`WsSessionManager.send` 失效会话被 `Iterator.remove` 清理，不抛 NPE。
4. 日志核对：后端 `ImService`/`WsSessionManager` 应输出发送/投递计数与失效清理记录。

## 3. 支付回流联调

### 3.1 联调脚本
```bash
# 本地模拟：复刻 PayService.notify 不变量（幂等/金额校验/状态同步/双向通知）
node scripts/pay-callback-sim.js --mock

# 真机/本地后端：向 /api/pay/notify 推送支付结果并核对订单
node scripts/pay-callback-sim.js --live http://localhost:8080 \
  --order-no NO20260921001 --pay-no P20260921 --amount 138000
# （可选）v3 回调：--v3（需真实签名；示例签名无效将被拒绝，验证验签护栏）
```

### 3.2 验收项
1. **正常回调**：`POST /api/pay/notify?payNo=&amount=` 后订单 `status` 由 `pending_pay → paid`，生成 1 条 `IN/PAY` 资金流水，买卖双方收到 `order_paid` 通知。
2. **幂等**：同一 `payNo` 重复回调，资金流水仍为 1 条，不重复记账（`PayService.notify` 已做幂等）。
3. **金额校验**：回调 `amount` 与订单金额不符 → 拒绝，订单保持 `pending_pay`。
4. **数据库核对**：
```sql
SELECT order_no, status, pay_status, pay_no, amount FROM t_order WHERE order_no='NO20260921001';
-- 期望：status='paid', pay_status='PAID', pay_no='P20260921', amount=138000（分）
SELECT * FROM t_fund_flow WHERE biz_no='P20260921';
-- 期望：1 条 direction='IN', type='PAY', amount=138000
SELECT id, type, title FROM t_notify WHERE type='order_paid' AND biz_id='NO20260921001';
-- 期望：买卖方各 1 条
```

## 4. 优惠券营销端到端

### 4.1 前端路径（小程序）
1. **领券中心**：`pages/coupon/center` → 调用 `GET /api/coupon/center`（分页，仅 ACTIVE 且未抢光）；点「立即领取」→ `POST /api/coupon/claim?couponId=`。
2. **我的优惠券**：`pages/coupon/my` → `GET /api/coupon/my?status=`（UNUSED/USED/EXPIRED 切换）。
3. **结算核销**：商品详情「立即购买」→ `pages/checkout/checkout` → `GET /api/coupon/available?itemId=&amount=`（按抵扣降序）→ 选券 → `POST /api/orders/create`（带 `userCouponId`），后端 `OrderService.createOrder` 调 `couponService.redeem` 重算 `payAmount`。
4. **订单详情抵扣**：`pages/order/detail` 展示「优惠券抵扣 −¥x」与实付；订单 `t_order.discount_amount` 落库。

### 4.2 后端关键不变量（与前端 Mock 一致）
- 抵扣计算 `CouponService.calculateDiscount`（纯函数）：满减（门槛满足才减）、无门槛（直接减，封顶不超商品金额）、折扣（商品×(1−rate)，封顶 maxDiscountAmount）。
- 领取 `claim`：活动状态 + 时效 + 限领 + **原子库存扣减**（`.setSql("claimed_count = claimed_count + 1")` + `lt(claimedCount,totalCount)` 行锁式判定），抢光抛 `COUPON_SOLD_OUT(30009)`。
- 核销 `redeem`：归属 + 状态 + 时效 + 范围 + 门槛校验，标记 USED 并绑定 `orderNo`，返回抵扣金额；不满足门槛抛错。
- 取消/关单 `releaseByOrder`：USED → UNUSED 并解绑订单号（释放券）。
- PC 发券 `CouponAdminController`：`POST /api/admin/coupon/create`（默认 ACTIVE）、`POST /api/admin/coupon/status`（ACTIVE/PAUSED/ENDED）。

### 4.3 PC 运营后台发券
- 左侧「财务与运营 → 发券管理」→ 列表展示券名称/类型/优惠内容/适用范围/领取进度/状态。
- 「新建优惠券」表单：券类型（满减/无门槛/折扣）、金额以**元**录入（提交时 ×100 转分）、适用范围（全场/指定类目/指定商品）、总量/限领/有效期。
- 状态操作：启用（ACTIVE）/暂停（PAUSED）/结束（ENDED）。

### 4.4 验收项与数据核对
1. 领券中心领取成功 → 「我的优惠券」出现该券（UNUSED）；库存 `claimed_count+1`。
2. 结算页可用券按抵扣降序，选择后实付 = 商品金额 − 抵扣；下单后订单 `discount_amount>0`，券 `status=USED`、`order_no` 绑定。
3. 取消该订单 → 券回退 `UNUSED`、`order_no` 置空（释放）。
4. 数据库核对：
```sql
-- 领取/核销状态
SELECT uc.id, uc.coupon_id, uc.status, uc.order_no FROM t_user_coupon uc WHERE uc.user_id=<买家ID>;
-- 订单抵扣落库
SELECT order_no, amount, discount_amount, coupon_id FROM t_order WHERE order_no='<订单号>';
-- 发放总量与已领
SELECT id, name, total_count, claimed_count, status FROM t_coupon;
```
5. **范围/门槛护栏**：折扣券 `scope_id` 已对齐真实类目（iPhone 叶子类目 111），仅匹配对应商品；满减券门槛未达时不进入「可用券」且不参与抵扣（前后端一致）。

## 5. 数据一致性核对清单（汇总）

| 表 | 期望状态（正常流程） |
|---|---|
| `t_order` | 支付后 `status=paid`；使用券时 `discount_amount>0`、`coupon_id` 非空 |
| `t_user_coupon` | 领取后新增 UNUSED；核销后 USED 且 `order_no` 绑定；取消订单回退 UNUSED 并解绑 |
| `t_coupon` | `claimed_count` 与已领记录一致；ACTIVE 券才可领 |
| `t_fund_flow` | 支付成功 1 条 IN/PAY；**幂等保证不重复记账** |
| `t_notify` | 支付成功、领券成功等事件双向触达买卖双方 |

## 6. 常见异常与代码护栏（对应实现）

- **IM 失效会话**：`WsSessionManager.send` 用 `Iterator.remove` 清理失效/失败会话，返回实际投递数，避免堆积与 NPE（IM 长连接稳定性）。
- **支付伪造/重复**：`PayService.notify` 幂等 + 金额校验 + 验签（v3），金额不符或重复回调均被拒（资损护栏）。
- **优惠券超发/重复领**：`claim` 行锁式原子库存 + 限领计数 + 活动时效校验；抢光抛 `COUPON_SOLD_OUT`。
- **抵扣资损**：`redeem` 强校验门槛/范围/时效；折扣封顶不超过商品金额；金额单位全链路「分」（契约护栏）。
- **取消订单券泄漏**：`releaseByOrder` 在关单/取消时释放，保证券可再次使用。
