# F-11.5 真机联调验证手册（V1.0.3 · IM 实时 / 支付回流 / 营销 2.0 / 发现效率）

> 适用范围：闲置集二手交易小程序 **V1.0.3** 分支（覆盖 F-11.5 生产基建真实化收尾验收）。
> 目标：在真机/本地后端环境，验证 **IM 实时消息收发稳定性与延迟**、**支付完成后回流链路（支付回调、订单状态同步）**、**营销 2.0（积分/拼团秒杀/邀请拉新）**、**发现效率（ES 检索/个性化推荐/搜索词运营/微信订阅消息）** 的端到端功能正常、数据一致、无异常遗漏。

## 0. 联调总览与验收口径

| 验证域 | 关键链路 | 验收口径（无异常遗漏） |
|---|---|---|
| IM 实时 | WS 连接 → 收发 → serverTime 打点 → 重连 | 送达率 ≥ 99%；P95 延迟可控；断线后指数退避重连成功；失效会话被清理 |
| 支付回流 | 支付回调 → 订单状态同步 → 资金流水 → 双向通知 | 回调后订单 `status=paid`；资金流水仅 1 条（幂等）；金额不符回调被拒；v3 真实签名被放行、伪造签名被拒 |
| 优惠券 | 领券中心领取 → 我的券 → 结算核销 → 订单详情抵扣 → 取消释放 | 库存原子扣减；门槛/范围/时效校验；抵扣金额正确；取消订单券回退 UNUSED |
| 积分体系(F-13.1) | 签到/交易/评价得积分 → 下单抵现 → 关单释放 | 得积分按配置比率；抵现封顶不超应付；并发超兑抛 POINT_NOT_ENOUGH；关单释放 |
| 拼团/秒杀(F-13.3) | 活动库存原子扣减 → 拼团成团/失败 → 关单释放 | 并发不超卖（affected 行网关）；参与唯一索引兜底；过期团自动 FAILED 并释放库存 |
| 邀请拉新(F-13.4) | 生成邀请码 → 绑定关系 → 首单返券 | 自邀自被拒；绑定唯一约束兜底；首单返券 best-effort 不阻断支付 |
| ES 检索(F-14.1) | ik 分词 → 筛选/聚合 → 索引重建 | 召回与排序符合预期；重建期间降级不报错 |
| 个性化推荐(F-14.2) | 行为加权 + 热度衰减 + 冷启动 | feed 按综合分排序；同城/冷启动生效 |
| 搜索词运营(F-14.3) | 热搜/历史/屏蔽词/同义词 | 热搜累加；屏蔽词拦截大小写不敏感；同义词归一化 |
| 订阅消息(F-14.4) | 关键节点 best-effort 触达 | 支付/发货/退款节点真实触达；拒收不重复打扰 |

## 2. IM 实时消息联调

### 2.1 联调脚本
```bash
# 本地模拟：验证前端延迟测量口径（无需后端，约数秒）
node scripts/im-loadtest.js --mock --rounds 100 --min-ms 15 --max-ms 60

# 真机/本地后端：两个用户登录取 JWT 各开一条 WS，互发并测延迟（需 npm i ws）
node scripts/im-loadtest.js --live http://localhost:8080 --users 2 --rounds 200
```
- WS 端点（对齐 `AuthHandshakeInterceptor`）：`ws(s)://<apiBaseUrl>/ws/im?token=<JWT>`。
- 前端延迟口径：`MessageVO.serverTime` 由后端 `ImService.push` 打点（`System.currentTimeMillis()`），`chat.js` 以 **接收时刻 − serverTime** 测算端到端延迟；`WsSessionManager.send` 返回实际投递数并清理失效会话。

### 2.2 验收项
1. 双端互发文本/议价卡片，消息在对方会话列表即时出现（延迟取 `serverTime` 口径）。
2. 杀掉一端网络/进程，另一端 `onError` 触发 **25s 心跳保活 + 指数退避重连（3s→30s）**，恢复后消息不丢（`seq` 去重）。
3. 高频压测（rounds=200+）下送达率 ≥ 99%，P95 延迟稳定；`WsSessionManager.send` 失效会话被 `Iterator.remove` 清理，不抛 NPE。
4. 日志核对：后端 `ImService`/`WsSessionManager` 应输出发送/投递计数与失效清理记录。

## 3. 支付回流联调

### 3.1 联调脚本
```bash
# 本地模拟：复刻 PayService.notify 不变量（幂等/金额校验/状态同步/双向通知）
node scripts/pay-callback-sim.js --mock

# 真机/本地后端：向 /api/pay/notify 推送支付结果并核对订单
node scripts/pay-callback-sim.js --live http://localhost:8080 \
  --order-no NO20260921001 --pay-no P20260921 --amount 138000
# （可选）v3 回调负向护栏：--v3（示例签名无效，将被后端拒绝，验证验签护栏）
# （正向）v3 真实签名联调：需商户私钥 + 证书序列号 + APIv3Key
node scripts/pay-callback-sim.js --v3-sign --live http://localhost:8080 \
  --pay-no P20260921 --amount 138000 --key ./merchant_key.pem --serial <CERT_SERIAL> --apiv3key <APIV3KEY>
# 说明：后端 IdlefishProperties 须配置对应证书序列号/公钥与 APIv3Key，签名方可被放行并落地支付成功。
```

### 3.2 验收项
1. **正常回调**：`POST /api/pay/notify?payNo=&amount=` 后订单 `status` 由 `pending_pay → paid`，生成 1 条 `IN/PAY` 资金流水，买卖双方收到 `order_paid` 通知。
2. **幂等**：同一 `payNo` 重复回调，资金流水仍为 1 条，不重复记账（`PayService.notify` 已做幂等）。
3. **金额校验**：回调 `amount` 与订单金额不符 → 拒绝，订单保持 `pending_pay`。
4. **数据库核对**：
```sql
SELECT order_no, status, pay_status, pay_no, amount FROM t_order WHERE order_no='NO20260921001';
-- 期望：status='paid', pay_status='PAID', pay_no='P20260921', amount=138000（分）
SELECT * FROM t_fund_flow WHERE biz_no='P20260921';
-- 期望：1 条 direction='IN', type='PAY', amount=138000
SELECT id, type, title FROM t_notify WHERE type='order_paid' AND biz_id='NO20260921001';
-- 期望：买卖方各 1 条
```

## 4. 优惠券营销端到端

### 4.1 前端路径（小程序）
1. **领券中心**：`pages/coupon/center` → 调用 `GET /api/coupon/center`（分页，仅 ACTIVE 且未抢光）；点「立即领取」→ `POST /api/coupon/claim?couponId=`。
2. **我的优惠券**：`pages/coupon/my` → `GET /api/coupon/my?status=`（UNUSED/USED/EXPIRED 切换）。
3. **结算核销**：商品详情「立即购买」→ `pages/checkout/checkout` → `GET /api/coupon/available?itemId=&amount=`（按抵扣降序）→ 选券 → `POST /api/orders/create`（带 `userCouponId`），后端 `OrderService.createOrder` 调 `couponService.redeem` 重算 `payAmount`。
4. **订单详情抵扣**：`pages/order/detail` 展示「优惠券抵扣 −¥x」与实付；订单 `t_order.discount_amount` 落库。

### 4.2 后端关键不变量（与前端 Mock 一致）
- 抵扣计算 `CouponService.calculateDiscount`（纯函数）：满减（门槛满足才减）、无门槛（直接减，封顶不超商品金额）、折扣（商品×(1−rate)，封顶 maxDiscountAmount）。
- 领取 `claim`：活动状态 + 时效 + 限领 + **原子库存扣减**（`.setSql("claimed_count = claimed_count + 1")` + `lt(claimedCount,totalCount)` 行锁式判定），抢光抛 `COUPON_SOLD_OUT(30009)`。
- 核销 `redeem`：归属 + 状态 + 时效 + 范围 + 门槛校验，标记 USED 并绑定 `orderNo`，返回抵扣金额；不满足门槛抛错。
- 取消/关单 `releaseByOrder`：USED → UNUSED 并解绑订单号（释放券）。
- PC 发券 `CouponAdminController`：`POST /api/admin/coupon/create`（默认 ACTIVE）、`POST /api/admin/coupon/status`（ACTIVE/PAUSED/ENDED）。

### 4.3 PC 运营后台发券
- 左侧「财务与运营 → 发券管理」→ 列表展示券名称/类型/优惠内容/适用范围/领取进度/状态。
- 「新建优惠券」表单：券类型（满减/无门槛/折扣）、金额以**元**录入（提交时 ×100 转分）、适用范围（全场/指定类目/指定商品）、总量/限领/有效期。
- 状态操作：启用（ACTIVE）/暂停（PAUSED）/结束（ENDED）。

### 4.4 验收项与数据核对
1. 领券中心领取成功 → 「我的优惠券」出现该券（UNUSED）；库存 `claimed_count+1`。
2. 结算页可用券按抵扣降序，选择后实付 = 商品金额 − 抵扣；下单后订单 `discount_amount>0`，券 `status=USED`、`order_no` 绑定。
3. 取消该订单 → 券回退 `UNUSED`、`order_no` 置空（释放）。
4. 数据库核对：
```sql
-- 领取/核销状态
SELECT uc.id, uc.coupon_id, uc.status, uc.order_no FROM t_user_coupon uc WHERE uc.user_id=<买家ID>;
-- 订单抵扣落库
SELECT order_no, amount, discount_amount, coupon_id FROM t_order WHERE order_no='<订单号>';
-- 发放总量与已领
SELECT id, name, total_count, claimed_count, status FROM t_coupon;
```
5. **范围/门槛护栏**：折扣券 `scope_id` 已对齐真实类目（iPhone 叶子类目 111），仅匹配对应商品；满减券门槛未达时不进入「可用券」且不参与抵扣（前后端一致）。

## 4.5 营销 2.0 与发现效率验收（F-13.x / F-14.x）

> 以下为 V1.0.3 新增并已推送的功能，真机验收应与上述 IM/支付/券一并覆盖。

### 4.5.1 积分体系（F-13.1）
- 路径：小程序「我的 → 积分」签到；下单勾选积分抵现；支付成功得积分；评价审核通过得积分。
- 后端：`PointService.signin/earnByTrade/earnByReview/redeem/releaseByOrder`；`PointCalculator` 纯函数。
- 验收点：签到每日幂等 + 连续加成；交易得积分比率 = `earnPointsPerYuan`（默认 2，即 100 元得 200 积分）；抵现封顶 `maxRedeemRatio=0.6` 且不超应付；并发超兑抛 `POINT_NOT_ENOUGH(30010)`；关单/取消 `releaseByOrder` 释放。
- 核对 SQL：
```sql
SELECT id, user_id, balance, signin_days FROM t_point WHERE user_id=<uid>;
SELECT id, type, delta, balance_after FROM t_point_log WHERE user_id=<uid> ORDER BY id DESC LIMIT 20;
```

### 4.5.2 拼团 / 限时秒杀（F-13.3）
- 路径：发现页活动列表 `GET /api/activity/list` → 详情 `GET /api/activity/detail` → 参与 `POST /api/activity/join` → 下单 `POST /api/orders/create`（带 `activityId`/`groupNo`）。
- 验收点：活动库存 `UPDATE ... SET stock=stock-? WHERE stock>=?` affected 行网关防超卖；同一用户对同一活动参与经 `(activity_id,user_id)` 唯一索引兜底；拼团满员 `SUCCESS`、超时 `@Scheduled` 扫描 `FAILED` 并归还锁定库存；关单/取消 `releaseOnClose` 归还。
- 核对 SQL：
```sql
SELECT id, stock, status FROM t_activity WHERE id=<aid>;
SELECT id, current_size, target_size, status FROM t_activity_group WHERE activity_id=<aid>;
```

### 4.5.3 邀请拉新 / 分销（F-13.4）
- 路径：`GET /api/invite/code` 取邀请码 → 被邀方 `POST /api/invite/bind?code=` 绑定 → 被邀方首单支付成功后自动返券（`PayService.onOrderPaid` → `InviteService.rewardFirstOrder` best-effort 经 `CouponService.grantCoupon` 直发）。
- 验收点：自邀自 `INVITE_SELF(30017)` 被拒；重复绑定 `INVITE_ALREADY_BOUND(30018)`；邀请码无效 `INVITE_CODE_NOT_FOUND(30016)`；绑定关系 `(inviter_id,invitee_id)` 唯一约束兜底并发；首单返券不阻断支付主流程。
- 核对 SQL：
```sql
SELECT code, user_id FROM t_invite_code WHERE user_id=<邀主>;
SELECT inviter_id, invitee_id, rewarded FROM t_invite_relation WHERE invitee_id=<被邀>;
```

### 4.5.4 ES 检索增强（F-14.1）
- 路径：`GET /api/search?keyword=&city=&categoryId=&condition=&priceMin=&priceMax=`；聚合 `GET /api/search/facets`。
- 验收点：ik 分词召回；同城/价格/成色/类目筛选；类目/成色/城市三维度聚合；全量重建 `IndexRebuildService` + 每日 03:30 `SearchScheduler` 兜底；ES 不可用时降级到 DB 不报错。

### 4.5.5 个性化推荐（F-14.2）
- 路径：`GET /api/recommend?city=&userId=&page=&size=`（userId 可选；缺省走同城优先+热度）。

### 4.5.6 搜索词运营（F-14.3）
- 路径：用户端 `GET /api/search/term/hot`、`GET /api/search/term/history`、`POST /api/search/term/record`；运营端 `POST /api/admin/search-term/block`、`/unblock`、`/synonym`、`/hotword/status`。

### 4.5.7 微信订阅消息（F-14.4）
- 路径：支付/发货/退款等关键节点由 `NotificationService.maybeAddSubscribe` best-effort 经 `RealWxSubscribeChannelImpl` 调微信 `subscribeMessage.send`。
- 验收点：access_token 内存缓存 + 提前 5 分钟刷新；失败 best-effort 不阻断主流程；用户拒收后不重复打扰。

## 5. 数据一致性核对清单（汇总）

## 6. 常见异常与代码护栏（对应实现）

- **IM 失效会话**：`WsSessionManager.send` 用 `Iterator.remove` 清理失效/失败会话，返回实际投递数，避免堆积与 NPE（IM 长连接稳定性）。
- **支付伪造/重复**：`PayService.notify` 幂等 + 金额校验 + 验签（v3），金额不符或重复回调均被拒（资损护栏）。
- **优惠券超发/重复领**：`claim` 行锁式原子库存 + 限领计数 + 活动时效校验；抢光抛 `COUPON_SOLD_OUT`。
- **抵扣资损**：`redeem` 强校验门槛/范围/时效；折扣封顶不超过商品金额；金额单位全链路「分」（契约护栏）。
- **取消订单券泄漏**：`releaseByOrder` 在关单/取消时释放，保证券可再次使用。
- **积分超兑/关单泄漏**：`redeem` 并发超兑抛 `POINT_NOT_ENOUGH`；`releaseByOrder` 关单释放积分，保证可再次使用。
- **秒杀超卖**：`beginOrder` 以 `UPDATE ... SET stock=stock-? WHERE stock>=?` affected 行网关 + `(activity_id,user_id)` 唯一索引兜底，杜绝超卖与重复参与。
- **邀请自邀/重复绑定**：`InviteValidator` 拦截自邀自与重复绑定，唯一约束兜底并发。
- **搜索屏蔽词**：`SearchTermFilter.isBlocked` 大小写不敏感拦截违规词，避免违规内容曝光。
- **订阅消息打扰**：`RealWxSubscribeChannelImpl` 失败 best-effort，拒收后不重复触达。
