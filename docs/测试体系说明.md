# 测试体系说明（F-15.4）

idlefish-backend 的测试分六层，按「离线可跑 / 需 MySQL / 需真实后端」三档组织，CI 跑全量、沙箱可跑离线子集。

| 层 | 位置 | 依赖 | 运行方式 | 说明 |
|---|---|---|---|---|
| ① 纯函数单测 | `src/test/.../service/*Test`（如 `RiskRuleFunctionsTest`、`TokenBucketTest`、`PointCalculatorTest`） | 无 IO | `mvn -o test -Dtest=XTest` | 营销/风控/限流核心算法纯函数，离线、确定性、无 Spring 上下文 |
| ② 契约一致性 | `src/test/.../contract/ContractConsistencyTest`、`ContractCompatibilityTest` + `src/test/resources/contracts/*.json` | 无 MySQL | `mvn -o test -Dtest='ContractConsistencyTest,ContractCompatibilityTest'` | 自研 JSON 契约；反射扫描全部 `*Controller` 断言契约端点真实存在（防漂移）+ 基线比对兼容性判定（ITER-T03） |
| ③ 集成测试 | `src/test/.../integration/ApiIntegrationTest`、`SubsystemSmokeTest` | **MySQL** | CI（`mysql:8.0` 服务容器）或本机 `mvn test` | MockMvc 跑关键链路（鉴权/金额契约/退款状态机/订单闭环） |
| ④ 离线冒烟 | `src/test/.../integration/SmokeRunner`（main 入口，免 surefire） | **MySQL** | `mvn -o test-compile && java ...SmokeRunner` | 沙箱离线启动 Spring 上下文，跑七大组件端到端 |
| ⑤ 全链路压测 | `scripts/loadtest/run-all.js` + `im-loadtest.js` + `pay-callback-sim.js` | 可选后端 | `node scripts/loadtest/run-all.js --mock\|--live <url>` | 编排 IM/支付回流压测，产出 `loadtest-report.json` |
| ⑥ 小程序 e2e | `miniprogram/e2e/run-e2e.js` + `flows.json` | 可选后端 | `node miniprogram/e2e/run-e2e.js --mock\|--live <url>` | 声明式核心旅程（登录→发布→下单→…），校验后端契约 |

> 沙箱无 MySQL / 微信开发者工具：① ② ⑤ ⑥ 的 `--mock` 可离线跑；③ ④ 需本机或 CI 的 MySQL。

## 契约（②）使用约定

- 契约文件（共 13 个参与校验）：`src/test/resources/contracts/*.json` 目录自动扫描（REQ-01，新增无需登记）；`admin.json`（敏感审批）与 `observability.json`（探针端点跨 profile 双实现）按先例排除；点号开头为元数据（`.contract-baseline.json` 基线快照、`.contract-exemptions.json` 豁免登记）。当前契约端点 **143 个**，全部命中。
- 每个端点字段：`method`、`path`、`auth`(none/user/admin)、`expectStatus`(可选)、`expectFields`(可选，响应 JSON 路径，支持 `name:type` 类型注解)、`notes`、`deprecated`(可选，标记后跳过漂移断言)。
- 新增/修改端点时**同步更新对应契约**：`ContractConsistencyTest` 拦截「契约写了但代码没有」的漂移；`ContractCompatibilityTest` 与基线比对，**删除端点/字段、改类型、改 auth、改 expectStatus 判不兼容并阻断**（REQ-04），新增端点/可选字段放行并列报告（REQ-05）。
- **基线再生**（有意的不兼容变更）：`mvn -o test -Dtest=ContractBaselineRegenerateTest -Dcontract.baseline.regenerate=true`，review 后提交 `.contract-baseline.json` 并重跑验证；禁止为绕过门禁随意再生。
- **豁免**（过渡期放行）：在 `.contract-exemptions.json` 登记 `key + 可选 field + reason + owner + expiresAt`，过期自动失效，报告可见（REQ-10）。
- CI 门禁：`.github/workflows/ci.yml` 的 `contract-gate` job（无需 MySQL）；请在仓库 Branch protection 将其设为 required check。
- 契约即文档：小程序/前端/测试同学以契约为准。
- 目录卫生：`target/test-classes` 可能残留已删除契约的旧拷贝，影响覆盖率计数报告；本地验证前先 `mvn clean`（CI 为干净检出，无此问题）。

## 压测（⑤）与 e2e（⑥）

- 压测与 e2e 的「真机」模式（`--live`）需运行中的后端（`docker compose` 起全栈见运维手册 §14）。
- 支付真实回调回流由 `pay-callback-sim.js --v3-sign` / `--live` 覆盖，不重复在 e2e 流里实现。
- 生成的 `loadtest-report.json` / `e2e-report.json` 已加入 `.gitignore`，不入库。
